# 🚀 Post-Push Verification Workflow

> **규칙**: `git push origin main` 실행 후, 사용자에게 "완료"를 보고하기 전에
> 아래 체크리스트를 **에이전트가 직접 실행**해야 한다.
> 사용자에게 "확인해주세요"라고 떠넘기지 말 것.

---

## Phase 1: Vercel 빌드 확인 (1-5분)

1. **Vercel 대시보드 확인**
   - 브라우저로 `https://vercel.com` 접속
   - cocotripkr 프로젝트 → 최신 배포 상태 확인
   - 커밋 해시가 push한 것과 일치하는지 확인
   - 상태가 **Ready** (준비가 된)인지 확인
   - 실패 시: 빌드 로그 캡처 → 사용자에게 즉시 보고

2. **빌드 실패 대응**
   - `tsc -b` 에러: 로컬에서 재현 → 수정 → 재push
   - 번들링 에러: Vercel 로그에서 원인 파악
   - 환경변수 누락: 사용자에게 Vercel 대시보드 확인 요청

## Phase 2: 프로덕션 스모크 테스트 (필수)

3. **메인 페이지 로드**
   - 브라우저로 `https://cocotripkr.com` 접속
   - 페이지 정상 로드 확인 (백지 아님)
   - Header/Footer 렌더링 확인

4. **변경된 페이지 직접 확인**
   - 이번 커밋에서 수정한 페이지를 직접 방문
   - 예: 플래너 수정 → `/planner` 확인
   - 예: PlanDetail 수정 → 기존 플랜 URL 확인
   - UI가 깨지지 않았는지 시각적 확인

5. **핵심 기능 체크** (해당되는 경우만)
   - WizardForm 표시 여부
   - PayPal 버튼 렌더링 여부
   - 언어 전환 동작 여부
   - PDF 다운로드 링크 존재 여부

## Phase 3: 보고

6. **체크 결과를 표로 정리**
   ```
   | 체크 | 결과 |
   |------|------|
   | Vercel 빌드 | ✅ Ready / ❌ Failed |
   | 커밋 일치 | ✅ {hash} |
   | 페이지 로드 | ✅ / ❌ |
   | UI 정상 | ✅ / ❌ |
   | 기능 확인 | ✅ / ❌ (상세 내용) |
   ```

7. **실패 항목이 있으면**
   - 즉시 원인 분석
   - revert 필요 여부 판단
   - 수정 가능하면 수정 → 재push → Phase 1부터 재실행

---

## 예외 사항

- **환경변수 관련 API 오류**: 에이전트가 해결 불가 → 사용자에게 Vercel 대시보드 확인 요청
- **외부 서비스 장애** (PayPal, Gemini 등): 코드 문제가 아니므로 보고만
- **모바일 실기기 테스트**: 에이전트 불가 → 사용자에게 요청 (Nice-to-have로 분류)

## 워크플로우 트리거

이 워크플로우는 다음 상황에서 **자동 실행**:
- `git push origin main` 완료 직후
- 사용자가 push를 승인/요청한 직후
- Vercel 재배포 트리거 후
