# 웹 자동 시각 검증 (verify-web)

**왜:** 코드 통과(tsc·빌드·unit·적대리뷰) ≠ 실제 동작. "코드는 되는데 실제론 안 됨"을 막는다. 운영자가 일일이 확인 못 하니 Claude가 dev를 직접 구동·판단한다. (운영자 비유: Brain OS=검증 중장비, Claude=운전자.)

## 원칙
- **snapshot으로 화면 내용·구조를 읽어** 판단한다(눈으로 보듯). screenshot 이미지는 보조.
- 로그인(구글)·결제(PayPal)는 제외 — 운영자가 처리(됐다 가정). 그 직전까지 검증.
- 안 뜨는 요소 / 깨진 레이아웃 / 콘솔 에러 = ❌. 정상 렌더 + 동작 = ✅.
- 추측 금지 — 실제로 클릭·읽고 본 것만 판단.

## 절차
1. preview 도구 로드: `ToolSearch` 쿼리 "preview"(preview_start/snapshot/click/fill/console_logs/screenshot/resize).
2. `preview_start` 로 dev 서버 확보(이미 떠 있으면 재사용).
3. 대상 화면 순회 — 각 화면마다: 이동 → 클릭/입력(구동) → `preview_snapshot`(내용 읽기) → 필요 시 `preview_screenshot` → `preview_console_logs`(에러 수집):
   - **홈** `/` — 히어로·TrustBadges·예시 섹션(ExampleItineraries)·지역 카드가 뜨나.
   - **예시 플랜** — 홈 예시 섹션에 서울/부산/제주 타임라인 카드(구간 교통·지도 링크·"예시" 배지)가 뜨나.
   - **플랜 상세** — `?localPlan=sample` 또는 로컬 plan harness 경로 — DayRouteMap(번호핀+선)·동선·StopCard "자세히" 텍스트·구간 교통이 뜨나.
   - **미리보기** — 위저드 결과/PurchaseSection 의 1일차 타임라인(시각·장소·교통·지도 링크), "--- ---" 가짜행 없나.
   - **위저드 입력** `/planner` — 단계 클릭·입력이 진행되나(결제 직전까지).
   - **투어/차터** — 목록·상세·예약폼이 뜨고, 결제 직전 BookingConsent(SMS 인증 버튼·약관 동의 체크)가 렌더되나.
   - **어드민** `/admin` — 비로그인 시 "Admin Access" 로그인 카드가 정상 렌더되나(로그인 후 화면은 운영자 눈확인 영역). 콘솔 에러 0.
   - **MOOD** `/mood` — 비로그인 시 "MOOD 포털/로그인이 필요합니다" 카드가 뜨나. 인트로 프리뷰는 `/mood?intro=mood`(자산 200 확인).
   ⚠️ dev 첫 로드가 빈 화면이면 vite dep 재최적화일 수 있음 — 리로드 1회 후 판정(콘솔에 "Re-optimizing" 로그).
4. **모바일도** — `preview_resize` 로 좁은 폭(~390px) 전환해 예시 섹션·미리보기 반응형 확인(데스크톱 전용 그리드가 안 깨지나).
5. 판단 + 보고: 화면별 ✅/❌ 표 + ❌ 사유(안 뜨는 요소·콘솔 에러 원문). ❌면 소스 읽고 원인까지.

## 모델 배분 (운영자 정책 — 쉬운 건 sonnet)
- 반복 구동·화면 캡처·순회 = **sonnet** (쉬움). subagent 위임 시 `opts.model: 'sonnet'`.
- 종합 판단·이상 근본원인 분석·수정 = **opus** (어려움).

## 자가 치유 루프 (검증 → 수정 → 재검증)
verify-web 에서 ❌ 가 나오면 무한정 보고만 하지 말고 **고치고 다시 검증**한다(최대 3회):
1. ❌ 화면의 원인을 소스에서 찾는다(snapshot 에서 안 뜬 요소·콘솔 에러 → 해당 컴포넌트).
2. **안전 경계로 분기:**
   - 🟢 **자동 수정 OK** — UI 안 뜸·깨진 레이아웃·오타·null 가드·import 누락·간단 로직. subagent(sonnet)로 고친다.
   - 🔴 **자동 수정 금지 → 멈춰 보고** — 결제·돈·금액·멱등성·식이안전(halal/vegan/allergy)·인증/보안·복잡 비즈니스 로직. 잘못 고치면 더 위험. 운영자에게 ❌ + 원인만 보고하고 멈춘다.
3. 수정 후 그 화면만 **재검증**(preview 재방문). ✅ 면 다음 화면, ❌ 면 1~2 반복(최대 3회).
4. 3회 후에도 ❌ 거나 🔴 영역이면 **멈추고 종합 보고**(고친 것·못 고친 것·왜).

## 강제 (머지 전 필수)
- 웹 plan-detail/planner/홈/예약 UI 를 변경해 머지하기 **전에 이 스킬을 실행**한다. ✅ 아니면 머지하지 않는다.
- 메모리 `feedback_verify_web_before_merge` + hook(settings.json)로 강제(안 하면 못 넘어가게).
