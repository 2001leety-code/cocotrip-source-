# 웹 시각 검증 (verify-web)

**왜:** 코드 통과(tsc·빌드·unit·리뷰) ≠ 실제 동작. "코드는 되는데 실제론 안 됨"을 막는다. Claude가 dev를 직접 구동·판단한다.

## 기본 = 읽기 전용
- **기본 동작은 검증만.** 화면을 구동·관찰하고 ✅/❌를 보고한다. **코드를 수정하지 않는다.**
- 자가치유(수정)는 사용자가 명시적으로 수정을 요청했거나 `--fix`로 실행했을 때만. "검증해"만 하면 고치지 않는다.

## 원칙
- **snapshot으로 화면 내용·구조를 읽어** 판단한다. screenshot 이미지는 보조.
- 로그인(구글)·결제(PayPal)는 외부 인증벽 — **"됐다 가정" 금지.** 그 직전까지 검증하고, 인증/실결제 경로는 **"미검증 — 운영자 확인 필요"** 로 분리 보고.
- 안 뜨는 요소 / 깨진 레이아웃 / 실제 에러 = ❌. 정상 렌더 + 동작 = ✅. 추측 금지 — 클릭·읽은 것만.
- **콘솔 메시지 판정:** 모든 로그를 실패로 보지 말 것. ❌ = 실제 error / unhandled rejection / 기능 장애. 허용 = dev 경고(Vite "Re-optimizing", HMR, sourcemap, 알려진 서드파티 deprecation 등). 애매하면 원문을 남기고 "경고(비차단)"로 표기.

## 범위
- **기본은 변경된 화면 우선.** 변경 diff와 관련된 화면만 검증한다.
- **전체 사이트 순회는 명시적 전체 검증일 때만.** 아래는 전체 검증 시 순회 목록:
  - **홈** `/` — 히어로·TrustBadges·예시 섹션·지역 카드
  - **예시 플랜** — 서울/부산/제주 타임라인 카드(구간 교통·지도 링크·"예시" 배지)
  - **플랜 상세** — `?localPlan=sample` 또는 `npm run plan:test` 하네스 — DayRouteMap(번호핀+선)·StopCard "자세히"·구간 교통
  - **미리보기** — 위저드 결과/PurchaseSection 1일차 타임라인, "--- ---" 가짜행 없나
  - **위저드** `/planner` — 단계 진행(결제 직전까지)
  - **투어/차터** — 목록·상세·예약폼·BookingConsent 렌더
  - **어드민** `/admin` — 비로그인 시 로그인 카드 렌더 + 콘솔 에러 0 (로그인 후 = 운영자 눈확인)
  - **MOOD** `/mood` — 비로그인 시 로그인 필요 카드. 인트로 = `/mood?intro=mood`
  ⚠️ dev 첫 로드 빈 화면이면 vite dep 재최적화일 수 있음 — 리로드 1회 후 판정.
- **모바일 ~390px** 도 `resize`로 확인(데스크톱 그리드 안 깨지나).

## 도구
1. preview 도구 로드(`ToolSearch` "preview") → `preview_start`로 dev 확보(이미 떠 있으면 재사용).
2. 화면 이동 → 클릭/입력 → snapshot(내용 읽기) → 필요 시 screenshot → console_logs(에러 수집).
3. **preview 도구를 못 쓰면** Playwright(`npm run test:e2e`) 또는 사용 가능한 브라우저 도구로 대체. **그마저 불가면 "미검증"으로 보고**(대충 통과 처리 금지).

## 규모별 배분 (강제 아님 — 판단)
- 반복 구동·순회 = sonnet 위임 가능. 종합 판단·근본원인 = opus. subagent 사용은 규모에 맞게 선택(1~2 화면이면 인라인으로 충분).

## 자가치유 (`--fix` 또는 명시적 수정 요청일 때만, 최대 3회)
1. ❌ 화면의 원인을 소스에서 찾는다.
2. **안전 경계로 분기:**
   - 🟢 **자동 수정 OK** — UI 안 뜸·깨진 레이아웃·오타·null 가드·import 누락·간단 로직.
   - 🔴 **자동 수정 금지 → 멈춰 보고** — 실결제·환불·충전·금액·멱등성·권한 변경·식이 안전(halal/vegan/allergy)·인증/보안·프로덕션 데이터·복잡 비즈니스 로직. 원인만 보고하고 멈춘다.
3. 수정 후 그 화면만 재검증. ✅면 다음, ❌면 반복(최대 3회). 3회 후에도 ❌거나 🔴면 멈추고 종합 보고.

## 머지 전 정책 리마인더
- 웹 plan-detail/planner/홈/예약 UI를 변경해 머지하기 전에 이 스킬로 실물 동작을 확인하는 것을 권장한다.
- `settings.local.json`의 PreToolUse hook은 **차단이 아니라 안내(리마인더)** 다 — `git push`/`gh pr merge` 시 이 확인을 했는지 상기시킬 뿐, 진행을 막지 않는다.

## 실기기 검증은 별도
- PWA standalone 실기기 동작은 dev로 증명 불가 → 항상 "미검증 — 운영자 확인 필요"로 분리.
