# 🌐웹 검증형 식사 후보와 결제 전 일정 연결

2026-11-02. 로컬 통합 작업 기준: PR1480 `d6ada8a7` + 식사/일정 수정. 운영 배포 완료 문서가 아니다.

## 실제 연결 범위

- `meal-plan-draft`는 기존 블록·경로·최종 검증으로 기준 일정을 만들고 소유자, canonical 입력, revision, fingerprint, DB version을 서버 초안에 저장한다. 실제 운영 DB 쓰기와 외부 유료 호출은 이번 로컬 검증에서 실행하지 않았다.
- `plan-meal-options`는 서버 소유 데이터로 후보를 재구축하고 선택 preview/확인/commit, 편집 및 transaction CAS를 수행한다. 임의 반경·우회시간 정책은 추가하지 않았다. 식사 체류60분과 이동은 분리하며 이전 식당 재방문도 정상 후보이다.
- Halal/Vegan/Vegetarian은 기존 신뢰 등급을 유지한다. 의료 알레르기를 새로 수집하지 않으며 누락을 '없음'으로 바꾸지 않는다. 명시적인 의료 요청·잘못된 값은 미확인으로 중단한다.

## 영업정보와 고객 고지

- 검증된 영업시간, 미확인, 알려진 휴무/시간충돌은 구분한다. 식이·동선·식사 시간·출국 조건을 만족하고 영업시간만 미확인인 일정은 `opening_unconfirmed`로 저장한다. 이 상태는 `verified_open`이 아니다.
- 사용자 승인 정책에 따라 영업시간 미확인을 결제 전에 고지한 후 일정 구매를 허용한다. 서버 주문은 고지 버전과 기록 시각을 함께 보존한다. 알려진 휴무/시간 충돌은 통과시키지 않는다.
- 출처URL/확인시각은 실제 영업시간 근거에서만 복사한다. 네이버 지역검색의 이름·주소 검색 성공은 영업시간 근거가 아니다. 현재 로컬 식당 인덱스3271행과 별도 영업근거0건은 운영 DB 전체 감사 결과가 아니다.
- 플랜 첫 화면과 공유·클라이언트/서버 PDF 첫 부분은4개 언어 방문 안내를 사용한다: 최신 운영시간/휴무 확인, 일정 추천과 예약·입장권 구매의 구분, 교통·대기·날씨에 따른 이동시간 변동, 실제 식이 요청이 있을 때 메뉴·조리 재확인. 카드에는 짧은 미확인 상태와 개별사항을 표시한다. 공통 알레르기 안내나 수집 UI는 추가하지 않았다.
- 공개 플랜은 원본 종교/의료 필드 대신 표시 전용 `visitDietaryRequest`를 사용한다. 이 값은 식이 검증이나 결제 권한으로 쓰지 않는다.

## 결제와 기존 주문 호환

- 신규 AI 주문은 서버가 `mealDraftBindingVersion:1`을 기록한다. 초안 소유자/revision/fingerprint/입력/DB/현재 유효성 및 고지 조건을 검증한다. 클라이언트가 보낸 일정·고지·이메일로 주문을 바꾸지 않는다.
- 버전과 초안 필드가 모두 없는 기존 snapshot만 종전 복구 경로를 유지한다. null·문자열·미지원 버전이나 고아 초안은 legacy로 강등하지 않는다.
- 세션 상실 시 기존 동일 주문 capability로 이미 전송된 결제의 상태 조회·조정은 가능하지만 새 capture POST나 초안 발급 권한을 주지 않는다. 기존 금액/통화/capture status/멱등성 검증은 유지한다.
- 신규 결제 후에는 동일 서버 일정을 기존 발급 claim/finalize 계약으로 저장한다. AI/경로/worker/Pass3 재생성 및 용량 초과 시 날짜 삭제를 하지 않는다. 무료 재생성 기본값·가격·완료 알림은 기존 계약을 유지한다.
