# 컨트롤타워: AI 없이 처리하는 운영 기능

## 승인과 이번 구현 범위

운영자는 남은 작업을 계속 진행하고 API나 AI 없이 프로그램으로 처리할 수 있는 일도 파악하도록 승인했다. 직전 제시한 api/chat.js 캡틴시트 가격 안내 정정도 진행 승인으로 반영한다. 실제 가격표의 7인승 추가금 33,000원과 일치시키는 안내 수정뿐이며 가격표·계산·주문·결제·환불은 변경하지 않는다.

- 회사 받은함: 이미 읽은 최대 100건 안에서 채널 선택, 제목/발신자 검색, 최근/오래된 순 정렬. 본문 자동 조회·AI 호출·추가 API 요청·검색어 저장 없음. 필터 변경 시 열린 상세를 닫고 첫 페이지로 이동한다. 계정 변경 시 검색어를 포함한 이전 상태를 초기화한다.
- 운영 요약: 출처별 조회 한도와 자료 확인 여부를 프로그램으로 판단한다. 한도에 닿으면 추가 대기 건 가능성을 안내하고, 조회 범위가 불명확하면 전체 건수로 단정하지 않는다. 원본 조회/업무 우선순위/금액/인증은 그대로다.
- 채팅 안내: 기본요금과 캡틴시트 별도 추가금을 구분한다. 기존 가격 검사가 다른 줄의 초과시간 요금 33,000원을 보고 통과하던 허점을 정확한 추가금 문장 검사로 교정한다. 실제 AI 응답 시험은 별도다.
- Lighthouse: 기존 기준 미달을 그대로 실패 처리하면서, 검토된 검사명과 수치만 기록한다. 인증 주소·쿼리·원문·자격정보·원본 보고서는 공개하지 않는다. 도구 반영과 실제 사이트 성능 개선은 다르다.

## 실제 코드로 확인한 구분

‘API 없음’은 계산할 입력이 이미 준비되어 있다는 조건이다. 클라우드 DB 조회, 채널 연결, 발송은 다른 단계다. AI 호출이 없더라도 서버·DB·저장소·통신 비용까지 0원이라는 뜻은 아니다.

| 업무 | AI 없이 가능한 부분 | 남는 연결/제한 | 실제 코드 |
|---|---|---|---|
| 예약·문의 우선순위 | 상태·예약일·대기시간으로 정렬 및 합계 | 원본 예약/문의는 Firebase 조회 | api/_shared/adminAiOpsAggregate.js |
| 중복 예약 정리 | 확인된 동일 식별자만 비교 | 이름만으로 합치지 않음 | dedupeConfirmedPendingMirrors |
| 받은 문의 찾기 | 채널·제목·발신자 검색과 시간 정렬 | 이번 구현. 이미 불러온 요약 100건 한정, 전체 검색 아님 | src/lib/selectInboxMessages.ts |
| 접수 확인 안내 | 승인된 고정 문구의 4언어 조합 | 실제 메일은 SMTP·DB 필요, 외부 채널 자동응대는 아직 OFF | api/_shared/inquiry-auto-ack-template.js |
| 가격 계산 | 정해진 거리·시간·차종·정책으로 산출 | 거리 입력의 실측은 별도, 실제 결제는 결제 연결 필요 | api/_shared/tour-price.js |

| Brain 작업 원장 | 실행 상태·생존 확인·변경 시에만 기록 | 로컬 PC가 켜져 있어야 함 | Brain brain/ops_ledger.py, runtime_supervisor.py |
| Brain 예약 발행 알림 | 예정 시각 확인·업체 성공 응답 판정 | Telegram 통신 필요. 실패를 완료로 기록하던 버그 수정 | Brain brain/content_queue.py |
| Brain 백업 | 매일 정해진 시각 SQLite 로컬 백업 | 같은 PC의 디스크 손실에는 보호 안 됨. 외부 백업 미구축 | Brain brain/db_backup.py |

## 권장 운영 방식

1. 명확한 조건·산수·시간 비교·중복 검사·화면 정리는 일반 코드가 담당한다.
2. 외부 채널 수집/발송은 공식 연결을 사용하되, 접수 확인 같은 고정 안내에 AI를 쓰지 않는다.
3. 고객 자유문장 해석·다국어 번역·여행 설명/제안처럼 필요한 부분만 AI를 선택 사용한다.
4. 불확실한 가격·환불·예약 확정은 AI 추측으로 실행하지 않는다. 승인된 계산/정책과 운영자 검토 경계를 유지한다.

## 전체 목표에서 여전히 남는 관문

- WhatsApp Business 앱 설치와 Cloud API 연결 완료는 다르다. 실제 수신은 아직 OFF다. Instagram/TikTok 메시지도 별도 권한/심사 조건이 있다.
- 업무문의 보관 기간은 후속 승인으로 일반 상담 종료 뒤 30일/미발송 초안 최대 7일로 확정했다. 진행 중·증빙 보호는 일괄 삭제하지 않는다. 구현·검증 범위는 CONTROL-TOWER-RETENTION-2026-09-09.md가 최신이며, 2시간 START는 여전히 수집 허용시간이지 삭제기한이 아니다.
- 고객 실발송, 새 계약, 유료 계정, 키 발급/등록은 이 코드 수정으로 완료되지 않는다. YCloud 보류, Google Places 제외, Hermes 이전은 후속이다.
- Brain 수정은 로컬 커밋이며 프로세스를 재시작하거나 안전 모드를 해제하지 않았다. PC OFF 무인운영은 별도 상시 서버 이전이 필요하다.
- 실제 폰 수신, 실제 채널 왕복, 업체별 청구 조회는 별도 검증해야 한다. 부산 플랜 중복 및 주간 다양성 실패·Lighthouse 실제 기준 미달은 근거 없이 완료 처리하지 않는다.

## 검증 기록

최종 출시 상태와 전체 검사 수치는 PR 및 Brain 공유 작업 기록에 남긴다. 합성 시험을 실제 고객 응대 시험으로 확대하지 않는다.

- 집중 검사: 받은함/검색/가격 안내 관련 49개, 운영 요약/문구 관련 113개, Lighthouse 도구 관련 137개 통과. 관련 ESLint 통과.
- 안정화된 최종 화면: 4언어 x 390/1280px 8개 브라우저 시나리오 통과. 추가로 한국어 두 폭에서 조회 한도/조회 실패를 구분했다. 고객 API/외부 요청은 차단한 합성 자료 검사이며, root가 검색 및 요약 사진 5장을 직접 확인했다.
- Brain 발행 예정 알림: HTTP 성공 및 JSON ok=true인 경우에만 완료 표시, 오류 원문에 자격정보가 섞이지 않도록 고정 오류로 변환. 관련 39개 모의검사와 Python 구문 검사 통과, 로컬 커밋 1fadd5b. 전송 성공 뒤 기록 실패/응답 유실의 기존 재시도 중복 가능성은 남는다. 서비스 재시작/실발송은 하지 않았다.

- Spark가 도구 없는 작은 코드 작성으로 selectInboxMessages를 실제 작성했다. root가 프로젝트 문체에 맞춰 적용·통합하고 회귀/실브라우저를 검수한다. 직접 파일 쓰기 제한을 다시 시도하지 않았다.
- 초기 로컬 브라우저 검사는 병렬 편집 중 미완성 문구 모듈 오류를 발견했다. 안정화 후 새 브라우저 문맥에서 다시 검사한다. 이후 선택 메뉴의 명시적 접근성 이름도 보강했다.
- 새로운 API/환경변수/DB 스키마/백그라운드 일정/기능 스위치 변경 없음. 기존 PWA·PDF·이메일·공유 화면을 새로 바꾸는 작업이 아니다.
