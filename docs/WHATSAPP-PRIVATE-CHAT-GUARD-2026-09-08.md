# WhatsApp 개인 대화 보호 - 2026-09-08

대상: 웹 cocotripkr.com / 개인 Android 컨트롤러의 AI 센터. 사용자는 같은 번호로 개인 대화를 한다고 확인했고, 업무 상담만 명시적으로 허용하는 보호 장치를 먼저 만드는 계획에 “응진행해 진행하면서 고치면되지”라고 승인했다. 실제 개인 대화를 읽어 분류하거나 옮기는 승인이 아니다.

## 이번 계약

- 본문을 외부 AI에 보내 개인/업무를 추정하지 않는다. Meta의 원본 서명, 회사 계정/번호, 수신 시작일/보관기간을 먼저 검사한다.
- 원본 텍스트가 정확히 `COCOTRIP SUPPORT START`인 새로운 요청으로 상담을 시작한다. 앞뒤 공백/개행/제어문자/추가 질문을 지운 뒤 일치시키지 않는다. 120초보다 오래된 START는 시작 근거가 아니다.
- 시작 메시지 자체는 받은함에 저장하지 않는다. 이후의 메시지만 최대 2시간 고정 구간에서 처리한다. Meta 시각은 초 단위이므로 시작과 같은 초의 본문도 제외한다. 고객은 시작 문구를 먼저 전송한 뒤 1초 이상 지나 문의를 보낸다. START 재전송이나 활성 구간의 START로 기한을 늘리지 않는다. 고객 번호가 같다는 이유만으로 영구 허용하지 않는다.
- `COCOTRIP SUPPORT STOP` 또는 정확한 `STOP`, 관리자 상담 종료, 만료는 이후 처리를 막는다. 개인 연락처 제외는 새 START도 막고, 제외 해제는 닫힘 상태만 만든다. 고객의 새로운 START가 있어야 재개한다.
- 과거 `history`, 연락처 동기화, 앱 발신 `echo`를 가져오지 않는다. START 이전/닫힘/미확인/제외/만료 메시지의 내용과 프로필은 저장/AI 전송/자동답장하지 않는다.
- 종료/차단의 확인과 수신 저장은 같은 Firestore 트랜잭션의 세션 문서를 공유한다. 동시에 처리할 때 닫힌 최신 상태로 재검사한다. 원본 발생 시각과 처리 시각을 모두 검사하고, 과거 START 재전송이 종료 장벽을 넘어 재개하지 못하게 한다.
- 새 API와 보호 장치는 메시지를 보내지 않는다. 고객 자동응대·AI 본문 처리·새 문의 푸시·실수신 활성화는 완료 범위가 아니다.

## 운영자가 조작하는 곳

AI 센터 → 회사 메일 · WhatsApp → 개인 연락처 보호. 개인정보 설정 대상 계정이 준비된 경우 수신을 켜기 전에도 제외를 등록할 수 있다. 번호는 국가번호를 포함한 숫자로 입력한다. 접힌 패널은 목록을 요청하지 않으며, 열린 상태에서만 명시적으로 목록을 읽는다. 제외/종료는 서버 성공을 확인해야 완료 표시하며 계정 변경/패널 닫힘 때 이전 요청을 버린다.

`GET /api/admin-whatsapp-privacy`는 기존 Firebase 관리자 토큰 검증 뒤 지정 계정의 최대 100개 상태만 반환한다. `POST`는 `close`, `block`, `unblock`과 정확한 상대 번호만 받는다. 본문 조회, 상담 강제 시작, 다른 계정 선택, 원본 대화 삭제 API는 없다. 미연결과 실제 0건, 조회 실패를 구분한다. 100개를 넘으면 전체 조회가 아님을 표시한다.

## 고객 진입

`/links`의 WhatsApp 상담 → `/whatsapp-support`. 2시간의 업무 상담 범위와 종료 방법을 읽고 사전 선택되지 않은 확인란을 선택한 뒤 WhatsApp을 연다. 외부 메시지 전송 버튼은 고객이 직접 누른다. 홈페이지 확인란은 서버 인증 증거가 아니며 **실제 동의 신호는 WhatsApp에서 받은 exact START**다. 직접 입력한 같은 START도 같은 계약으로 처리한다.

기존 다른 WhatsApp 직접 문의 링크는 보존한다. 그 경로에서 START 없이 도착한 대화는 자동 수집되지 않으며 원래 휴대폰 앱에서 사람이 확인한다. 결제·PDF·예약 후속 링크를 일괄 교체하지 않는다.

## 저장과 보호의 한계

- `whatsapp_inbox_sessions`: 계정/상대 번호/상태/시작·종료 시각/최근 시작 식별자만 저장한다. 문서 ID의 해시는 익명화가 아니다. **상담이 없을 때 받은 STOP**은 지연 START를 막을 해시 식별자와 최소 종료 장벽만 만들며 상대 번호·본문·프로필은 넣지 않는다.
- 세션/제외/종료 장벽은 고객 원문이 아니라 처리 통제 상태다. 이 기록을 TTL로 임의 삭제하면 차단과 재전송 방어가 사라지므로 자동 삭제하지 않는다. 정상 상담 메시지의 보관기간과 `external_inbox_messages.expiresAt` TTL 확인은 기존 실행안과 같다.
- 현재 `firestore.rules`는 명시되지 않은 경로를 기본 거부한다. 새 컬렉션에 클라이언트 허용 규칙을 추가하지 않았고, 관리자 서버의 검증된 API만 사용한다. 실제 운영 규칙과 이 파일의 배포 일치는 실연결 때 별도 확인한다.
- 새 정상 수신에 `whatsappPolicyVersion:1`, `whatsappSessionId`를 기록한다. 관리자 목록/직접 ID 읽기에서도 확인하여 정책 근거가 없는 과거 WhatsApp 문서를 숨긴다. 기존 저장 문서나 원래 앱 대화를 삭제하는 기능은 아니다.
- 개인 메시지도 Meta에서 웹훅 서버로 전달될 수 있다. 이 장치는 **수신 후 저장·AI 처리 경계**이지 서버로 전송되는 것 자체를 막는 보장은 아니다. 인프라의 요청 본문 로깅 여부는 운영 환경에서 별도 확인해야 한다.
- 허용된 2시간 안에 상대가 사적인 내용을 보내는 것까지 완벽히 구분할 수 없다. 개인 연락처를 제외하고 업무 상담 안에서는 개인 내용을 보내지 않도록 안내한다.
- 개인정보 API 준비(`ready`)는 고정 WABA/번호와 개인정보 모드 설정 준비다. 수신 스위치(`enabled`), 전체 인증 준비, 실제 메시지 수신 성공은 각각 다르다.

## 출시 및 실제 번호 연결 관문

1. 합성 자료로 비허용 본문 저장 0, 명령 변형, 과거/만료/미래/중복/경합, 관리자 인증/계정 분리, 네 언어/모바일/PC 조작을 검증한다. 실제 개인 메시지/키/DB 접근은 하지 않는다.
2. 정상 build/전체 단위 검사/린트/오답노트/PR 검사 후 묶음 출시한다. 실패한 검사를 숨기거나 임계값을 낮추지 않는다.
3. **Vercel 대시보드**에서 운영자가 기존 서버값과 신규 `WHATSAPP_INBOX_PRIVACY_MODE=explicit_sessions_v1`을 등록한다. AI가 환경값을 읽거나 넣지 않는다. Preview/Development 실제 수신은 계속 차단된다.
4. 현재 앱이 일반 WhatsApp인지 Business인지, 기존 대화 보존/공존 조건을 확인하고 나서 업무 번호를 연결한다. 테스트 번호 발급과 기존 번호 이전은 다르며 삭제/전환을 임의 실행하지 않는다.
5. 개인 연락처 제외, 시작시각/기간/실제 TTL, 인프라 로그, 테스트 계정 수신·중복·STOP·차단·AI 센터 표시를 확인한 뒤에만 실운영 수집을 켠다. 실제 고객에게 시험 답장을 보내지 않는다.

## 실제 Meta 상태 (앞선 턴의 직접 화면 확인)

사용자가 휴대폰에서 Facebook 2단계 인증을 설정했다고 알린 뒤, PC 비즈니스 지원 홈은 개인 계정에 `광고 문제 없음`을 표시했고 2단계 인증 미설정 제한 경고가 사라졌다. PC 계정 센터의 낯선 기기 안내는 별도로 남아 있었다. 이미 승인받은 동일 약관/포트폴리오에서 한 번 재시도하여 WhatsApp 환영 화면 및 `WhatsApp 테스트 번호 받기 완료됨`을 확인했다. 테스트 환경만 생성됐으며 기존 업무 번호/메시지/토큰 발급/서버값은 변경하지 않았다. 브라우저는 탭 26 하나만 유지했다. 이번 코드의 검증·머지·배포 결과는 완료 후 별도 기록한다.

## 로컬 검증 기록

- 개인 메시지 지연 도착의 같은 초 경계, 제외 해제 후 목록 누락 성공 오판, DOM 반영 전 초점 복귀, 없는 배경 토큰, 제목 중복, 새 주소의 운영 404를 실제 검사에서 찾고 보완했다.
- 새 정책/인증/저장 집중 6파일 258개 통과, UI 집중 48개 통과. 실패했던 문서 동기화 시간 초과와 경로 매칭을 따로 재현·재검사한 2파일 127개도 통과했다. 전체 재검사는 작업 수만 4개로 제한하고 검사 범위/시간 기준은 유지했다.
- 최종 `npm run build`, 변경된 TS/TSX 린트, JS 7파일 실제 Node 권장 규칙 린트(오류/경고 0), 네 언어 2,214키 일치, 용량 8그룹 통과. 기본 빌드의 기존 대형 청크/혼합 import 경고는 남아 있다.
- 실제 Chrome 합성 화면 390/1280px × 4언어 × 관리자/고객 16조합 통과. 관리자 종료/제외·해제/5건 페이지 이동, 동의 초기 비선택/언어 변경 초기화/정확한 시작 링크, 44px 조작 높이, 글자 대비 최소 6.918:1, 가로 넘침·페이지 오류 0을 확인했다. root도 직접 조작하고 사진을 확인했다. 증거는 로컬 `tmp/whatsapp-privacy-ui-20260908/report.json`과 PNG이며 고객 자료나 실제 서버 변경이 아니다.
- ADB 도구는 있으나 이번 직접 조회에서 연결 기기는 0대였다. 일반 WhatsApp/Business 설치 종류를 확인하지 못했으며 휴대폰 설정·기존 대화에 접근하지 않았다.
- 최종 전체 `npx vitest run --maxWorkers=4`: 785파일 10,817 PASS / 기존 7 TODO, 314.25초 (18:10:41 KST 시작). 검사 생략이나 기준 완화는 없다. PR/배포 결과는 확정 후 실행 기록에 이어 적는다. 실제 수신/AI 답장/휴대폰 알림은 아직 검증하지 않았다.
