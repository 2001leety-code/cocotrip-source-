# AI 운영센터 오답노트 — 2026-08-31

- `data-cocotrip-navigation=reload`는 새로고침 방식만 뜻한다. 이것만으로 서비스워커 자동 업데이트 성공을 판정하지 말고, 수동 새로고침 없는 이전→새 배포 버전 전환과 실제 Android 실행을 별도로 확인한다.
- 새 worktree는 Vercel 프로젝트 연결 정보가 없다. 이 상태에서 `vercel curl`을 먼저 실행하면 폴더명으로 빈 프로젝트를 만들 수 있으므로, 기존 CocoTrip Vercel 프로젝트에 먼저 link한 뒤 조회한다.
- Windows 서명 보관 폴더의 상속을 끈 뒤 새 로컬 파일을 만들면 접근 규칙이 비어 실행이 막힐 수 있다. 키·암호·실행기 생성 후 파일별 ACL과 실제 release 명령을 다시 확인한다.
- `verify:prepush`의 실수 패턴 검사는 `origin/main..HEAD`만 보므로 변경이 아직 커밋 전이면 `no changes`로 건너뛴다. 커밋 뒤 같은 검사를 다시 실행해야 근거가 된다.
- Android 의존성은 표시 이름을 좌표로 추측하지 않는다. 공식 Google Maven의 실제 groupId·artifactId·version과 POM/AAR 존재 여부를 확인한 뒤 고정한다.
- `/admin`에서는 고객용 프로모션·쿠키·가입 모달·하단 탭·하단 여백을 모두 격리하고, 운영에 필요한 PWA 업데이트 알림만 유지한다.
- Firebase `getIdToken`을 변수로 떼어 호출하면 `User`의 `this`가 깨질 수 있다. 반드시 `user.getIdToken()`으로 호출한다.
- Windows에서 `.bat`를 `shell: true`로 실행하면 공백·메타문자 경로가 깨지거나 명령 주입 위험이 생긴다. Java 실행 파일에 wrapper·도구 인수를 배열로 직접 전달한다.
- `apksigner`의 모든 실패를 미서명으로 간주하지 않는다. ZIP 무결성·`aapt2` 패키지명·정확한 종료 코드와 `DOES NOT VERIFY` 메시지를 모두 확인하고 하나라도 다르면 실패한다.
- 개인용 sideload도 실제 서명키·SHA-256·공개 `assetlinks.json`·서명된 release APK가 모두 없으면 출시할 수 없다.
- `bookings`, `pending_bookings`, `mood_bookings`는 같은 표의 복사본이 아니다. 한 컬렉션만 읽고 “전체 예약”이라고 표시하지 않는다.
- 고객 이름·이메일·전화번호·여행일이 같다는 이유로 예약을 합치지 않는다. 확정된 입금 대기 문서와 정식 예약의 주문·예약·캡처 식별자가 정확히 일치할 때만 mirror로 정리한다.
- `P0` 순위 값은 숫자 `0`이다. `rank || fallback`을 쓰면 `0`이 fallback으로 바뀌어 가장 긴급한 일이 뒤로 밀린다. 키 존재 여부를 따로 검사한다.
- 과거 `decision_queue` 문서에 `status`가 없으면 정규화 결과는 `pending`이다. 처리 대상 여부도 원본 값이 아니라 이 정규화된 상태로 판단한다.
- 원본 조회 실패를 `0건`으로 바꾸지 않는다. 성공한 원본은 계속 보여주되 실패한 원본과 부분 집계 상태를 화면에 명시한다.
- 재시도 큐 읽기가 실패했을 때 빈 배열을 집계 함수에 넘겨 `정상 · 대기 없음`으로 표시하지 않는다. 해당 자동화 카드도 `상태 확인 실패`로 닫아 둔다.
- 통합 화면은 읽기 전용이다. 예약·결제·환불·배차 상태를 바꾸는 API를 연결하지 않고, 응답에도 고객 개인정보를 싣지 않는다.
- GitHub 정기검사 실행 이력이 아직 연결되지 않았다면 정상으로 추정하지 않는다. `미연동`으로 표시하고 실제 Actions 화면으로 연결한다.
