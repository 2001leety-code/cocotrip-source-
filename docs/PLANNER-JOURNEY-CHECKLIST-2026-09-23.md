# 플래너 실제 흐름 점검 기준과 결과

## 기준과 범위

- 기존 기능 목록은 91개 점검 항목이다: 고객 38, 관리자 28, MOOD 16, 웹·Brain·Python 연결 9. 이는 확인 완료 개수가 아니다. 정본과 기능별 후속 검사는 `docs/qa/feature-checklist.csv`에서 관리한다. 이 문서는 CHECK-03의 플래너 근거다.
- 각 항목은 **실제 진입 경로 → 입력 → 요청 → 처리 → 결과**를 연결해 본다. 코드·테스트 파일이 있다는 사실만으로 통과 처리하지 않는다.
- 공통 조건: 정상 입력, 필수 입력 누락, 처리 실패와 재시도, 중복 실행, 입력·표시·저장 내용의 일치. 적용하지 않은 조건과 이유도 남긴다.
- 상태는 `코드 확인 / 로컬 부분 확인 / 로컬 흐름 확인 / 운영 확인 / 실패 / 미확인`으로 구분한다. 운영 완료는 실제 대상 환경에서 결과까지 확인했을 때만 쓴다.
- 비용·중복 청구·데이터 손실·권한·식이 안전을 우선하고, 다음으로 핵심 고객 흐름, 오류 복구, 화면 표시를 본다. 보호 규칙을 통과시키려고 완화하지 않는다.
- Astra가 범위·격리·최종 검수, Luna가 중복 방지 구현과 저장·공유 검사를 맡았다. 바탕화면 보고서는 더 생성하거나 갱신하지 않는다.

## 재현한 결함과 최소 수정

- 무료 미리보기 버튼을 같은 처리 주기에서 두 번 누르면 실제 요청·서버 핸들러가 2번 실행됐다. 버튼의 로딩 상태가 화면에 반영되기 전 공통 처리 함수가 중복 진입했다.
- `usePlannerHandlers`의 무료 제출 함수에 진행 중 표시를 두고 `finally`에서 해제했다. 같은 훅 인스턴스에서 진행 중인 두 번째 제출은 무시하고, 완료·실패 후 명시적 재시도는 허용한다.
- 수정 전 회귀 검사는 3개 통과·중복 1개 실패, 수정 후에는 재시도 검사까지 5개 통과. 다중 탭·새로고침을 포괄하는 서버 중복 차단을 추가한 것은 아니다.
- 결제·가격·인증·재생성·식이·DB 스키마·의존성·환경변수 설정은 변경하지 않았다.

## 남은 완료 조건

1. **CHECK-03 전체는 부분 완료**: 무료 미리보기와 유료 요청 사이의 실제 결제창은 합성 주문으로 대체했다. 서버 legacy·block 동기 및 block worker 함수의 생성→저장→실제 get-plan 재조회는 연결했고, 그 JSON으로 상세→PDF를 실행했다. 하나의 실계정 브라우저 세션 전체 성공으로 합산하지 않는다.
2. 3pass·스트리밍 생성·실제 worker 예약/재시도, 실제 계정/목록·운영 생성/저장·발송·공개 링크 권한·실폰트·기기별 공유는 미확인이다. `p230` 기존 검사는 소스 계약·초기화/분기 검사도 포함하므로 worker 전 과정 근거가 아니다.
3. 저장 실패 시 응답은 500이고 문서는 없지만 발급 claim은 `COMMITTING`에 남는다. 중복 발급 방지 상태이므로 임의 해제하지 않았다. 실제 주문 복구 정책과 운영 절차는 별도 확인한다.
4. 이번 유료 모델·운영 DB·실제 발송 호출은 0회다. 이전 PR #1411의 실제 모델 검사·배포 결과와 구분한다. 이 문서는 로컬 검증 근거이며 이번 출시 결과는 PR과 최종 보고에서 별도로 확인한다.

## 후속 정리에서 확인한 원인

- Gemini 보정 경로에 언어가 전달되지 않아 기존 4개 언어 안내가 한국어 기본값으로 생성됐다. 동기·worker의 공통 경로에도 언어를 전달하고, 합성 숙소 출발/복귀 표시명을 함께 보정했다. 장소 검색용 이름·주소와 사용자 입력 숙소, 요금 계산식은 유지한다.
- 수정 중 undefined 컨텍스트로 교통 보정이 생략되는 회귀를 전체 처리 결과의 교통 설명 존재 검사로 잡아 보완했다. 소스 문자열만 맞추는 새 검사는 버리고 실제 저장 결과 검사를 남겼다.
- 보완 후 플래너·숙소·투어 저장조회 관련 3파일 29개 통과. 별도 플래너·경로·숙소·block 회귀 4파일 51개 통과(실행 집합이 겹치므로 합산하지 않음).
