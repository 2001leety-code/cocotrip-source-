# MOOD 예약 변경·공유 오답노트 — 2026-08-12

## 2026-08-26 예약시간 숫자 입력 회귀 방지

- 제어되는 숫자 입력에서 빈 문자열을 즉시 숫자 기본값으로 바꾸면, 9를 지운 뒤 6을 입력할 때 6이 아니라 16으로 붙을 수 있다.
- 편집 중인 문자열과 계산·저장에 쓰는 유효 숫자를 분리하고, 빈값은 편집 중 유지하되 포커스를 옮기거나 제출할 때 복원 또는 차단한다.
- 예약시간 입력은 반드시 `9 → '' → 6` 순서로 조작한 뒤 저장 요청의 `durationHours`가 숫자 6인지 회귀 테스트로 잠근다.

## 2026-08-24 경로 순서 편집 회귀 방지

- 화면 순서는 항상 `출발지 → 경유지 → 도착지`여야 하며 역할은 저장값이 아니라 현재 행 위치에서 정한다.
- 주소와 `courseMoodPercentages`를 서로 다른 배열로 움직이면 비용 부담 주체가 다른 장소에 붙는다. `id·주소·부담률`을 한 행 상태로 묶어 추가·삭제·되돌리기·재정렬한다.
- 부담률만 바뀔 때 경로 API를 다시 호출하지 않는다. 경로 요청 서명에는 서비스와 정리된 주소 순서만 포함한다.
- 주소나 순서가 바뀐 즉시 이전 지도·예상 금액·잔액을 무효화하고, 현재 요청 서명과 일치하는 새 응답이 와야 다시 표시하고 저장을 허용한다.
- 빈 중간 행을 서버가 제거할 때 부담률도 같은 행 기준으로 함께 제거해 `지점 수 === 부담률 수` 계약을 지킨다.

## 요구사항을 잘못 해석한 지점

- 비용 분담은 전체 금액의 50:50이 아니다.
- 화면에 붙은 번호 하나를 한 코스로 보고 전체 금액을 번호 수로 똑같이 나눈 뒤, 각 번호에 지정된 부담자에게 합산한다.
- 예: 총 100,000원, 5코스, 1번만 MOOD 부담이면 MOOD 20,000원 / 인플루언서 80,000원이다.
- 나눗셈의 원 단위 나머지는 마지막 코스에 붙여 코스 합계와 전체 금액이 반드시 같게 한다.

## 발견한 근본 원인과 방지책

1. 기존 예약 변경이 `새 예약 → 기존 예약 취소` 두 단계라 중간 실패 시 이중 예약·이중 차감 가능성이 있었다.
   - 예약 본문, 잔액 차액, 개정 번호, 감사 기록, 중복 요청 응답을 한 트랜잭션에서 저장하는 변경 API로 바꿨다.
2. 예약 경로 계산 실패를 기본요금 예약으로 계속 처리해 경유지·거리·톨비가 빠진 과소청구가 가능했다.
   - 사용자가 주소를 보낸 경우 경로 실패·손상 숫자는 모두 쓰기 전에 거부하도록 잠갔다.
3. 예약 생성에 중복 요청 키가 없어 두 번 누르기나 응답 유실 재시도 때 이중 차감될 수 있었다.
   - 수기·AI 예약 모두 같은 요청 내용에는 같은 키를 재사용하고, 서버에서도 키를 필수로 검증한다.
4. 예상 톨비와 실제 톨비가 한 값으로 섞여 전달됐다.
   - 정산에서 예상 유지 / 미지불 / 실제 금액을 구분하고, 변경 사유와 실제 동선을 최종 자료에 보존한다.
5. 완료 예약이 저장된 실제 동선 대신 예약 당시 동선을 보여 줬다.
   - 완료 상태는 최종 동선과 최종 비용을 우선 사용하고, 지도 경로선과 번호 핀을 캡처 카드에 함께 표시한다.
6. 저장된 금액·시급·잔액이 문자열이나 비정상 숫자여도 0원처럼 처리되는 경로가 있었다.
   - 돈을 읽고 쓰는 API 경계에서 안전한 정수만 허용하고, 손상 데이터는 조용히 보정하지 않고 중단한다.

## 회귀 잠금

- 예약 생성: 경유지 한도, 경로 실패, 손상 경로, 순차·동시 중복 요청, 신용한도, 코스 부담자 순서.
- 예약 변경: 권한, 상태, 개정 충돌, 증액·감액·동일 금액, 중복 요청, 감사 기록, 실제 지도 스냅샷.
- 정산: 실제·미지불 톨비, 수동 조정, 경로 재측정, 시급·잔액 무결성, 변경과의 경합.
- 공유: 100,000원/5코스의 20,000원·80,000원 분담, 원 단위 나머지, 개인정보 제외, 복사 실패 대체 경로.
- 화면: 개발 전용 인증 우회 하네스로 모바일·데스크톱 지도, 변경 모달, 부담자 전환, 저장 흐름을 직접 확인한다.
