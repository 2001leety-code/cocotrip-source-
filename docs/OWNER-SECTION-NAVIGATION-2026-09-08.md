# 운영센터 가로 메뉴: 키보드 초점 잘림 보완

대상: 웹 운영센터 `/admin/ai-center`. 사용자 요청에 따라 추가 실물 검사에서 발견한 기존 불편도 계속 고쳤다. PR1382의 비용 카드나 숫자를 바꾸는 작업은 아니다.

## 원인과 변경 범위

- 원래 가로 스크롤 메뉴는 일부 글자만 보이는 링크에도 키보드 초점을 줄 수 있었다. 실제 390px에서 한국어 비용 링크의 노출 폭은26.42px, 중국어는14px였다. 0~500ms 관찰에도 그대로였고, 변경 전1080bad8의 동일 함수/CSS와 이전7개 항목을 재현한 브라우저에서도 같은 문제가 생겼다. 링크 자체 크기44px와 실제 노출 폭은 다르다.
- `:focus-visible`인 링크만 메뉴의 실제 표시 영역과 대조해 필요한 만큼 `nav.scrollLeft`를 보정한다. 0~최대 스크롤을 벗어나지 않으며 이미 전체가 보이면 움직이지 않는다.
- CSS·8개 링크·주소·문서 세로 위치·키 이벤트·클릭·조회·API·고객정보·권한·가격·알림·설치 파일은 바꾸지 않았다. 새 환경변수·운영 플래그도 없다. 마우스 초점과 수동 가로 스크롤을 그대로 둔다.
- 전체 메뉴를 항상 한 화면에 펼치는 변경은 아니다. 가로로 넘기는 구조는 유지하되 키보드로 선택한 항목은 완전히 보이게 한다.

## 검증

- 새 단위검사15개: 네 언어/8개 주소/44px, 좌우 일부 잘림, 브라우저가 이미 노출한 경우, 첫·마지막 범위, 테두리, 반복 초점, 포인터/수동스크롤, Tab·Enter 기본 동작. 관련3파일63 PASS, 독립 검토자도 새15개 재실행 PASS. ESLint/`git diff --check` 정상.
- 실제 Chrome 390/1280px×4언어8조합 PASS. 앞으로8개·뒤로7개씩120회 키보드 초점에서 링크 전체 노출, 초점만으로 문서scrollY/hash 변경0, 초점 링 유지. 비용 클릭/Enter8회와 다음Tab의 비용설명SUMMARY 이동8회도 정상이다.
- 모바일 마지막 scrollLeft는ko216/en501/ja327/zh232, 역방향 처음은 모두0. 비용 노출 폭은ko26.42→108.14px, zh14→105.66px로 실제 링크 전체가 보인다. 44px 실크기/가로 페이지 넘침0/브라우저 오류0을 확인했다.
- 가짜 공개 설정·개발 하네스만 사용했다. 실제 고객 API·외부·쓰기 허용0이며 이 화면에서 그 요청 시도도0이다. root가 한국어·중국어 모바일 결과 사진을 직접 확인했다. 근거 `tmp/owner-cost-nav-fixed-20260908/summary.json`과24장, 변경 전 비교는 `tmp/owner-cost-nav-native-20260908/summary.json`이다.

## 오답노트

native Tab을 쓴다고 일부 가린 항목이 자동으로 완전히 드러나는 것은 아니다. 44px 실크기와 초점 링뿐 아니라 잘림을 제외한 실제 노출 영역, 정·역방향Tab, 양 끝 스크롤 경계를 검사한다. `scrollIntoView`로 문서 세로까지 움직이지 않고 필요한 가로 컨테이너만 보정한다.
