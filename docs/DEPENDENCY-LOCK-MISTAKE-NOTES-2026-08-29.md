# 의존성 자동 갱신 잠금파일 오답노트 (2026-08-29)

## 무엇이 실패했나

- Dependabot 의존성 PR 두 개가 대상 패키지와 무관한 Puppeteer 하위 패키지 13개를 `package-lock.json`에서 삭제했다.
- GitHub 검사는 테스트를 시작하기도 전에 `npm ci`에서 종료됐다.
- DOMPurify는 웹과 Brain이 같은 정확 버전을 써야 하는데, 웹 PR만 올려 교차 저장소 계약도 어긋났다.

## 근본 원인

자동 생성된 잠금파일을 패키지 이름과 버전만 보고 정상이라고 판단했다. 이 저장소는 Puppeteer 선택 의존성과 웹·Brain HTML 정제 결과를 함께 고정하므로, 의도하지 않은 삭제와 교차 저장소 버전까지 확인해야 한다.

## 재발 방지

- 의존성 PR은 `package.json`뿐 아니라 잠금파일의 의도하지 않은 삭제를 확인한다.
- 기존 잠금파일을 보존하고 대상 패키지만 증분 갱신한다.
- 깨끗한 설치(`npm ci`) 후 빌드, 전체 단위 테스트, 커버리지, 크기 제한을 모두 실행한다.
- DOMPurify처럼 출력 바이트 계약이 있는 패키지는 웹과 Brain을 함께 갱신하고 양쪽 테스트를 통과시킨다.
- 자동 PR이 깨졌다면 억지로 머지하지 않고 최신 `main`에서 검증된 대체 PR 하나로 승계한다.
