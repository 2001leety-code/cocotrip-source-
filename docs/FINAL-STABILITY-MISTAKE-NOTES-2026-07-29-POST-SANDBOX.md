# Sandbox 실결제 뒤 추가 오답노트 — 2026-07-29

대상: 🌐웹(cocotripkr.com, Vercel=prod), PR #1187.

## 1. 단위 테스트의 25초 제한을 운영 시간으로 착각

- 잘못된 가정: booking processor는 25초 안에 끝날 것이다.
- 실제 결과: Preview Sandbox에서 결제 후처리에 약 33초가 걸렸다. 결제·예약·적립은 완료됐지만 호출자는 먼저 timeout을 받아 재처리 대기 상태를 남겼다.
- 수정: Capture 호출에만 45초 제한을 명시했다. 함수의 60초 실행 제한에는 여유를 남기고, 45초를 넘으면 기존 재처리 원장이 계속 복구를 맡는다.
- 잠금 테스트: Capture가 `timeoutMs: 45_000`을 넘기는지 소스 회귀 테스트로 고정한다.

## 2. 화면 검사의 오류 화면을 정상 기준 이미지로 보관

- 잘못된 가정: 인증이나 fixture가 없어도 화면 비교가 통과하면 시각 회귀 검사가 유효하다.
- 실제 결과: Preview 전용 Firebase fixture가 정상 연결되자 기존 기준 이미지가 로딩·오류 상태였음이 드러났다.
- 수정: 실제 플랜이 로드된 Preview 결과를 새 기준 이미지로 삼는다.
- 재발 방지: Preview 시각 검사에는 전용 Firebase 사용자와 고정 plan ID를 반드시 주입한다. 인증 없이 만든 기준 이미지는 정상 화면 증거로 인정하지 않는다.

## 3. 선언한 색인과 실제 배포를 같은 것으로 착각

- 잘못된 가정: 워크플로 파일을 추가했으니 Firestore 색인이 배포될 것이다.
- 실제 결과: `run:` 한 줄 안의 콜론 때문에 YAML 자체가 깨져 작업이 0개로 종료됐다. 자격증명도 없어서 문법만 고쳐도 성공처럼 건너뛰는 구조였다.
- 수정: 명령을 YAML 블록으로 바꾸고, Firebase 배포 자격증명이나 프로젝트 ID가 없으면 명확히 실패하게 했다.
- 재발 방지: YAML 파싱과 색인 파일 단위 테스트를 먼저 통과시키고, 실제 GitHub 작업 성공과 운영 화면의 오류 해소까지 확인한다.
