# 보호된 미리보기 검사 도구 최초 설치

## 승인과 범위

운영자가 2026-09-08 "나머지 목표까지 진행해"로 직전 제안한 도구 전용 선행 PR/최초 설치·머지 절차를 승인했다. PR #1380의 검토된 검사 도구 6파일과 이 기록만 main에 먼저 적용한다. 제품의 src/api/public, Firebase/결제/권한 규칙, 패키지, 고객 자료, 환경변수 값은 변경하지 않는다. 기존 Lighthouse assert 정책도 그대로다.

## 원인과 해결 순서

- 검사는 main의 신뢰한 도구만 실행하도록 설계했으나 첫 PR은 그 도구를 아직 main에 설치하기 전이다. 실제 run34135716421은 LHCI_TRUSTED_HELPER_NOT_ON_MAIN으로 수집 전에 실패했다. 이를 앱 성능 측정 결과나 통과로 세지 않는다.
- 이 선행 PR에 한해 최초 설치 전의 검사 미실행 상태를 명시하고, 다른 필수 검사·빌드·독립 검토를 통과한 뒤 승인된 정상 머지 절차로 도구를 설치한다. 관리자 강제 머지, 보호 설정 변경, 검사 실패 숨김은 하지 않는다.
- 설치 후 현재 제품 PR head와 SHA가 정확히 일치하는 READY Preview의 숫자 Deployment ID로 main의 검사를 실행한다. 테스트만 추가해도 head가 바뀌면 이전 ID는 거부된다. 같은 앱 URL을 재사용할 수 있는 visual 검사와 혼동하지 않는다.
- 인증/실제 세 경로 수집 성공과 사이트의 필수 성능 판정은 별개다. 기존 알려진 성능 항목이 실패하면 실패로 보고하며 기준을 낮추지 않는다.

## 보안과 비용

기존 GitHub Secrets의 VERCEL_AUTOMATION_BYPASS_SECRET은 지정 호스트 /robots.txt의 Node 요청에만 전달한다. 리디렉션을 따라가지 않고, 브라우저에는 해당 호스트의 Secure/HttpOnly 쿠키만 설치한다. PR 코드를 CI 도구로 실행하거나 원문 로그/보고서를 공개 저장소로 올리지 않는다. 키의 조회·발급·변경, 실제 고객 조회·메시지 발송은 없다. 배포 파일이 아닌 도구/검사 변경만 묶어 한 번 푸시한다.

## 회귀 확인

2026-09-08 로컬에서 두 스크립트 구문 검사, 변경한 JS/TS 4파일 ESLint, 전용 2파일 116개 테스트를 실제 실행해 통과했다. 독립 검토자도 같은 116개 테스트와 도구 6파일을 별도로 검토했다. Windows 줄바꿈만 정규화해 비교한 도구 6파일은 검토된 be5f3825와 동일하고, origin/main의 Lighthouse assert 설정과도 깊은 비교로 동일함을 확인했다. 전체 빌드·전체 단위 테스트·용량·오답 패턴·훅 순서 검사는 정상 푸시 전 훅에서 추가 실행한다.

동일 저장소/정확한 PR head/비정상 출처 거부, 비밀값을 포함할 수 있는 오류 문자열 비노출, 쿠키 범위/정리, 누락·중복·리디렉션·수집 오류·필수 판정 실패 거부를 가짜 브라우저와 보고서로 검사한다. 실제 인증은 도구 설치 뒤 별도로 확인해야 한다.

오답노트: 신뢰 기준을 main으로 정한 도구는 최초 설치 순서도 분리해야 한다. 테스트-only의 Vercel 성공 표시나 자동 통과를 실제 측정으로 대신하지 않는다. 숫자를 녹색으로 만들기 위해 검증기를 느슨하게 하지 않는다. 실패 이유가 필요해도 URL·원문 로그·전체 보고서를 공개하지 말고, 검토된 고정 정책 audit ID·유한 숫자·상한 있는 누락 건수만 안전 요약으로 남긴다.
