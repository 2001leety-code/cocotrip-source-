# 오답노트 — 투어 사진 감사 후속 (2026-08-22)

PR #1336 (정류지 사진 오배선 8건 교정) 을 **독립 리뷰로 다시 검사**해서 나온 구멍들.
원 PR 의 사진 판정 자체는 전부 맞았다(md5 14/14 일치, 새 사진 6장 육안 확인 통과).
문제는 **"다 고쳤다"고 믿게 만든 잠금장치에 뚫린 구멍**이었다.

---

## 함정 1 — "눈으로 다 확인했다"면서 그림 안에 박힌 AI 워터마크를 못 봤다

**증상**: `/서울/해방촌-남산야경.jpg` 좌하단에 **"AI로 생성한 콘텐츠"** 글자가 픽셀로 박혀 있다.
이 파일이 서울 나이트투어 해방촌 정류지 사진 + 그 투어 갤러리 + `/region/seoul` 지역 갤러리
3곳에 실려 있었다. 실제로 가는 투어에 AI 로 만든 그림을 실은 셈.

**왜 못 봤나**
- 사진 감사가 "이 사진이 그 장소인가"만 봤다. **"이게 사진이긴 한가"는 안 봤다.**
- 원 PR 은 이 파일을 "촬영 지점이 해방촌인지 미확인(파일명 근거만)"으로만 적고 통과시켰다.
  촬영 지점을 따질 대상이 애초에 아니었다.
- EXIF·C2PA 같은 파일 속 제작 정보는 **전부 지워져 있다**(스크립트로 확인). 단서는 그림 안 워터마크뿐.
- 규격도 달랐다: 998×666 / 196KB. 주변 한국관광공사 원본은 5000픽셀대 / 1MB 이상.
  **크기가 혼자 튀면 출처가 다르다는 신호**다.

**다음부터**
- 사진을 정류지에 붙이기 전 **네 귀퉁이를 먼저 본다**(워터마크·로고·생성 표기).
- 해상도가 주변 원본과 자릿수부터 다르면 출처를 의심한다.
- 잠금: `tests/unit/tour-stop-photo-integrity.test.ts` 의 `AI_GENERATED_PHOTOS` 차단 목록.
  정류지·갤러리 **양쪽** 을 막고, 그 파일의 md5 도 같이 고정해서 파일이 바뀌면 다시 열어보게 한다.

## 함정 2 — 중복 검사를 md5 로 "자동화"하면서 정작 사고 유형을 놓쳤다

**증상**: 원 PR 이 하드코딩 중복 그룹을 지우고 md5 자동 계산으로 바꿨다. 좋아 보였는데,
**같은 사진을 webp 와 jpg 로 각각 구우면 바이트가 달라 해시가 갈린다.**

지워진 그 그룹이 정확히 그 경우였다:

| 경로 | md5 |
|---|---|
| `/1uA0qa_반포대교(1).webp` | `032D8487…` |
| `/Type1_반포대교_…1uA0qa(1).jpg` | `4E0753C4…` |
| `/서울/서울 (11).jpg` | `4E0753C4…` |
| `/서울/서울 (18).jpg` | `4E0753C4…` |

즉 **2026-06-10 사고(반포 분수 사진 4벌 → 나이트 갤러리에 3번 노출)를 다시 넣어도 초록**이 된다.
실제로 살아 있던 사례도 있었다 — 서울 시티투어 갤러리에 `/JnR5Ie_경복궁(1).webp` 와
`/서울/서울 (3).jpg` 가 동시에 있었고, **둘 다 3648×5472 로 근정문 앞 같은 인물 2명을 찍은 같은 사진**이다.

**다음부터**
- 자동 계산이 사람 목록보다 항상 낫다고 보지 말 것. **해시는 "바이트가 같은가"만 안다.**
- 손으로 만든 목록을 지울 때는 **그 목록이 잡던 것을 새 방법도 잡는지** 먼저 확인한다.
- 잠금: `FORMAT_VARIANT_GROUPS` (사람이 두 파일을 열어보고 묶은 목록) 를 md5 검사와 **함께** 돌린다.

## 함정 3 — 갤러리와 정류지를 따로 검사하면 "같은 사진 두 번"을 놓친다

**증상**: 부산 투어에서 갤러리는 `/부산/부산 (5).jpg`, 광안리 정류지는
`/Type1_부산 광안대교_…BTr8Za(1).jpg` 를 썼다. **두 파일은 md5 가 같다**
(`5D1CB386C0858A694080BBBFF8B789ED`). 같은 850KB 를 경로만 달리해 **두 번 내려받고**
한 화면에 같은 사진이 두 번 나왔다.

검사는 갤러리 목록과 정류지 목록을 **따로** 해싱하고 있어서 이 조합은 영원히 안 걸렸다.

**다음부터**
- 중복은 "한 페이지가 실제로 부르는 URL 전체"를 기준으로 본다. 목록이 나뉜 건 코드 사정일 뿐이다.
- 같은 **경로**가 두 목록에 있는 건 정상(브라우저가 1번만 받는다). 문제는 **다른 경로 + 같은 내용**.
- 잠금: 갤러리+정류지를 합치고 경로 기준으로 먼저 중복 제거한 뒤 md5 로 묶는다.

## 함정 4 — 사진이 틀렸는데 "빈칸이 보기 안 좋다"고 다른 장소 사진으로 때우면 안 된다

투어 상세 SCENE 매거진의 "인사동·익선동, 골목의 점심" 장면이 `/서울/서울 (1).jpg` 를 쓰고 있었는데,
그건 **북촌한옥마을 사진**이다(`Type1_북촌한옥마을_라이브스튜디오_dJ6Ara.jpg` 와 md5 동일).
바로 위 장면이 이미 북촌이라, 같은 동네 사진 두 장 중 하나를 "인사동"이라 캡션하고 있던 셈.

`public/` 에 인사동·익선동 실사진은 **없다**(검색 확인).
→ 다른 장소 사진으로 바꾸지 않고 **장면 자체를 뺐다**(서울 5 → 4장면).
경주가 4장면인 것과 같은 원칙이다: *"늘리려면 진짜 사진을 먼저 넣어라."*

**원칙**: 틀린 사진은 **빼는 게 맞다.** 비슷해 보이는 사진으로 메우면 오배선이 이름만 바뀐다.
