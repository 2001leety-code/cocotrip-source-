# MOOD 다중 업체 견적 작성기 오답노트 (2026-08-28)

- 견적 금액은 화면에서 다시 계산하지 않는다. 서버의 버전 고정 요금표와 정수 분·미터·원 계산 결과만 미리보기와 복사문에 사용한다.
- 빈 숫자 입력을 `0`으로 바꾸면 무요금 업체가 저장될 수 있다. 필수 숫자는 빈 값·소수 오용·범위 초과를 저장 전에 막고 서버에서도 다시 거부한다.
- 화면에는 `50km`, `10%`, `3시간`처럼 사람이 읽는 단위를 보여 주되 서버 경계에서만 미터·0.01% 단위·분 정수로 바꾼다.
- AI가 `includeInRoute=false`를 임의로 만들면 거리요금이 줄어든다. 원문 근거가 없으면 경로 포함으로 되돌리고, 분석 결과는 관리자가 명시적으로 확인해야 한다.
- 프로필 수정·보관은 `expectedVersion` 없이 허용하지 않는다. 현재 문서, 불변 버전 사본, 전·후 감사 기록을 한 트랜잭션에 남긴다.
- 개발 하네스에 같은 가격 공식을 복제하지 않는다. 승인된 508,500원 서버 응답 fixture 한 건만 사용해 두 번째 가격 기준이 생기지 않게 한다.
- 견적 API는 실제 예약·잔액·충전·정산·결제 컬렉션과 호출 경로를 공유하지 않으며, `2001leety@gmail.com` 관리자 판정을 서버에서 다시 확인한다.
- 기존 소스가드가 경로 응답의 정확한 필드 문자열을 잠그고 있으면 역호환 필드 추가도 전체 테스트에서 실패한다. `distanceMeters`를 추가할 때 기존 `km` 필드 유지와 소스가드를 함께 갱신한다.
- 개발 하네스의 `값 || '확인 필요'`도 번역 폴백 검사에 잡힌다. 고정 한국어 문서 fixture의 미확정 표시는 지역화 함수로 오인되지 않도록 이름 있는 상수로 분리한다.
- 별도 worktree에서 로컬 화면을 열 때 Firebase 공개 설정이 비어 있으면 앱이 렌더 전에 멈춘다. 운영 키를 복사하지 말고 오프라인 하네스에만 형식이 맞는 더미 공개 설정을 주고 모든 외부 요청을 차단한다.
- 지역 충돌을 화면의 `stopOrder` 배열로만 들고 있으면 주소 수정·순서 이동 뒤 낡은 경고가 견적을 막는다. 원문에서 확인한 `sourceRegion`을 각 장소에 붙여 보존하고, 서버가 현재 주소·현재 순서로 충돌을 매번 다시 계산한다.
- 숫자 입력을 `Number()`로 바로 바꾸면 `0x10`·`1e2` 같은 형식도 통과한다. 수동 거리는 화면에서 일반 십진수 형식을 먼저 확인하고 서버에서는 JSON 숫자만 다시 허용한다.
- 실제 자동 추정기가 없는 비용 정책을 화면에 노출하면 `0원`처럼 오해되는 견적이 생긴다. 주차비는 직접 입력 또는 요금 포함만 허용하고, 포함 비용은 `0원`이 아니라 `요금에 포함 · 별도 청구 없음`으로 쓴다.
- 운행거리 제외 장소도 일정에는 남길 수 있지만 이동 문장은 실제 경로 포함 장소끼리만 이어야 한다. 제외 장소에는 `차량 운행거리 산정 제외`를 명시하고 거짓 출발 문장을 만들지 않는다.
- 견적 계산 중 입력이 바뀌면 늦게 도착한 이전 응답이 새 입력의 문서처럼 보일 수 있다. 입력 변경 때 진행 중 요청을 중단하고 요청 세대를 올려, 현재 세대의 응답만 표시·복사한다.
- 인증 객체가 바뀐 뒤 새 권한 조회를 기다리는 동안 이전 관리자의 견적 상태를 남기면 다른 계정에 고객 일정이 노출될 수 있다. 계정 식별자가 바뀌거나 로그아웃되는 즉시 관리자 데이터와 견적 탭을 닫고, 이전 조회 응답도 폐기한다.
