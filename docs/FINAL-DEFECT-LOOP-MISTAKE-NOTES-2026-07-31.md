# 최종 잔여 결함 수리 오답노트 — 2026-07-31 (PR #1196)

대상: 🌐웹(cocotripkr.com, Vercel=prod). 배포 SHA `c0956672` · 운영 번들 `entry-DByIjVea.js`.

이 라운드는 앞선 판촉 P0 라운드(#1191~#1195)에서 "고쳤다" 고 적어 둔 항목들을 **실제 코드와
운영 원문으로 다시 확인**하면서 시작했다. 여덟 건 중 여섯 건이 "고쳤다는 기록은 있는데
실제로는 안 고쳐졌거나 절반만 고쳐진" 상태였다. 그래서 이 문서의 주제는 하나다 —
**"고쳤다"의 근거가 무엇이었는가.**

## 1. 같은 상품에 환율을 두 벌 두고 "표시가=결제가" 라고 적은 실수

- 잘못된 생각: 차터 USD 는 고정환율 1400 으로 통일했으니 어디서 찍어도 같은 값이 나온다.
- 실제 결과: `/charter` 공개 본문은 **$87**, 결제·서버는 **$89** 였다. 본문만
  `formatPrice`(= 표시환율 `policy_krw_per_usd` 1430)를 쓰고 있었다.
  124,800/1430 = 87.27 → "$87" / 124,800/1400 = 89.14 → "$89".
  게다가 **같은 문단**에 "1 USD = 1400 KRW, 표시 금액이 결제 금액" 이라고 적혀 있었다.
  즉 화면이 스스로를 반박하고 있었는데 아무도 두 숫자를 나란히 놓고 보지 않았다.
- 재발 방지: 금액을 만드는 함수를 **하나로** 두고(`lib/charterUsd.ts`), 반올림까지 거기 넣는다.
  그리고 결제 화면 파일들이 표시환율 함수(`formatPrice`·`convertFromKRW`·`KRW_PER_USD`)를
  **임포트조차 못 하게** 잠금 테스트를 건다. "쓰지 말자" 는 규칙은 지켜지지 않는다 —
  못 쓰게 만들어야 지켜진다.
- 파생 교훈: 통화 표기를 언어별로 바꾸면(ja=¥, zh=¥) "표시=결제" 문장은 **번역할수록 거짓**이
  된다. 결제는 늘 PayPal USD 이기 때문이다. 그래서 표기를 `₩124,800 ($89 USD)` 로 통일했다 —
  두 숫자를 같이 적으면 어느 언어에서도 참이다.

## 2. 번역만 만들어 두고 화면에 배선하지 않은 실수

- 잘못된 생각: `estimatePayDisclaimer` · `estimatePayAgreeLabel` 이 4개 언어로 다 있으니
  추정가 정산 조건은 고지되고 있다.
- 실제 결과: 두 키의 **화면 호출처가 0건**이었다. 번역 파일에만 존재했다. 실제 고지는
  결제 **후** 메일·바우처·월렛패스에만 있었고, 결제 **전** 공개 본문 4개 언어는 정반대로
  "결제 후 추가 청구는 하지 않습니다" 라고 단정하고 있었다.
- 재발 방지: 번역 키를 추가할 때 **호출처가 있는지**를 같은 PR 에서 확인한다. i18n parity
  검사는 "4개 언어에 다 있다" 만 보고 "누가 쓰는가" 는 안 본다. 고지 문구는 특히 —
  존재 여부가 아니라 **노출 여부**가 준수의 기준이다.
- 파생 교훈: 결제 후 고지는 결제 전 동의를 대신하지 못한다. 서류를 늘리는 것과 동의를 받는
  것은 다른 일이다.

## 3. SDK 메서드를 개별 mock 으로 바꿔 놓고 "실동작을 검증했다" 고 믿은 실수

- 잘못된 생각: `opt_out_capturing()` 과 `reset()` 이 둘 다 호출되는 걸 테스트가 확인하니
  철회는 확실히 반영된다.
- 실제 결과: **posthog-js 1.404.0 의 `reset()` 은 첫 줄에서 `consent.reset()` 을 호출해
  opt-in/out 저장값을 삭제한다.** 즉 `opt_out → reset` 순서는 방금 건 opt-out 을 스스로
  취소하고 있었다. 화면상 "철회함" 인데 SDK 상태는 "미선택" 이라 다음 세션부터 다시 수집된다.
  기존 테스트는 두 메서드를 각각 `vi.fn()` 으로 대체했기 때문에 **부작용이 존재하지 않는
  세계**를 검증하고 있었다. 호출 여부만 맞으면 통과했다.
- 재발 방지: 외부 SDK 의 **상태**가 결론인 검증은 진짜 SDK 를 띄운다
  (`tests/unit/posthog-optout-real-sdk.test.ts`). 근거는 "우리가 뭘 불렀나" 가 아니라
  `has_opted_out_capturing() === true` 와 **네트워크 요청 0건**이다.
  그 파일의 첫 케이스는 일부러 **옛 순서의 버그를 재현**한다 — 버그를 재현하지 못하는
  테스트는 그 버그를 막지 못한다.
- 파생 교훈: 라이브러리를 올릴 때 "우리가 부르는 메서드" 만 보지 말고 그 메서드가 **내부에서
  또 무엇을 부르는지** 본다. 이번엔 minified 소스를 직접 읽어서 찾았다.

## 4. `page_path` 만 깨끗하게 만들고 다 됐다고 생각한 실수 (배포 실측에서 발견)

- 잘못된 생각: `trackPageView` 에서 쿼리스트링을 떼고 경로만 보내면 GA4 에 민감 값이 안 간다.
- 실제 결과: **gtag.js 는 `dl`(document location)·`dr`(referrer)을 자기가
  `window.location.href` / `document.referrer` 에서 채운다.** 우리가 `page_path` 를 아무리
  깨끗하게 보내도, 이미 동의한 재방문자가 `/s/xxx?token=…` 로 바로 들어오면 그 토큰이 `dl` 로
  나갔다. **로컬 단위 테스트는 전부 통과했고, Preview 네트워크를 실제로 뜯어보고 나서야
  파라미터 모양에서 발견했다.**
- 재발 방지: 전송 라이브러리가 **우리 대신 채우는 필드**를 목록으로 확인한다. 우리가 넘기는
  것만 보면 절반만 본 것이다. `page_location`·`page_referrer` 를 명시해 덮어쓰고,
  page_view 뿐 아니라 **모든 이벤트**에 붙인다.
- 파생 교훈: 이번 라운드에서 **배포 후 실측으로만 잡힌 유일한 결함**이다. 23번 오답노트
  ("배포하고 실측해야 나오는 결함이 또 있었다")가 그대로 반복됐다. 단위 테스트는 우리가
  상상한 경계만 검사한다.

## 5. 분석 방어를 "차단 목록" 으로 만든 실수

- 잘못된 생각: PII 필드 이름(`email`·`phone`·`address`…)을 모아 막으면 개인정보는 안 나간다.
- 실제 결과: 차단 목록은 **우리가 미리 떠올린 이름**만 막는다. 나중에 생긴
  `revisionNote`·`allergies`·`prefillHotel`·`token` 은 그대로 통과했다. 목록은 코드보다
  느리게 자란다.
- 재발 방지: **허용 목록(기본 거부)** 으로 뒤집었다(`lib/analyticsProps.ts`). 새 속성을
  보내려면 목록에 이름을 추가해야 하고, 추가하는 순간 "이게 개인정보인가" 를 한 번 생각하게
  된다. 그게 이 목록의 진짜 목적이다.
- 파생 교훈: 허용 목록으로 바꿀 때는 **지금 실제로 쓰는 키를 전수 조사**해서 먼저 넣는다.
  안 그러면 측정이 조용히 죽는다(그리고 아무도 모른다).

## 6. `authorUid` 만 지우고 "uid 를 제거했다" 고 적은 실수

- 잘못된 생각: 공개 응답에서 `authorUid` 필드를 없앴으니 uid 는 안 나간다.
- 실제 결과: 같은 응답의 `images` 가 Firebase Storage **다운로드 URL** 이었고, 그 경로가
  `community/{uid}/...` 다. **사진이 한 장이라도 붙은 글은 uid 를 그대로 흘리고 있었다**
  (덤으로 Storage 다운로드 토큰까지). 기존 테스트는 `images: []` 인 문서만 넣어서 통과했다.
- 재발 방지: 개인정보 검사는 **응답의 모든 중첩 문자열**을 훑는다(필드 이름 목록이 아니라).
  그리고 테스트 픽스처는 **비어 있지 않은 실제 형태**여야 한다 — 빈 배열은 아무것도 증명하지
  않는다.
- 재발 방지 2: 밖으로 나가는 식별자를 **불투명 토큰**으로 바꾸되, 파일은 옮기지 않는다.
  `sha256(postId|원본URL)` 은 레거시 글에도 그대로 적용되므로 **물리 이동 0건**으로 끝났다.
  마이그레이션이 필요해 보이면, 먼저 "식별자만 바꾸면 되는가" 를 묻는다.

## 7. SPA 폴백 한 줄이 사이트 전체를 "존재하는 페이지" 로 만든 실수

- 잘못된 생각: `/((?!api/).*)` → `/index.html` 은 SPA 의 표준 설정이다.
- 실제 결과: 오타 URL·삭제된 링크·봇이 찍는 아무 경로가 전부 **HTTP 200 + 홈 HTML** 이었고,
  원문에는 `robots: index, follow` 와 `canonical: /` 가 박혀 있었다. 검색엔진에는
  "존재하는 페이지가 무한히 많고 전부 홈과 같은 내용" 으로 보인다(soft 404 + 중복 색인).
  런타임 `<meta robots>` 는 JS 가 돈 뒤에야 붙으므로 원문만 받는 크롤러에겐 없는 것과 같다.
- 재발 방지: **알려진 라우트만** index.html 로 보내고 나머지는 진짜 404 를 내는 함수로 보낸다.
  라우트 목록이 두 벌이 되는 것을 막기 위해, 테스트가 **App.tsx 에서 라우트를 직접 읽어**
  vercel.json 매칭을 검증한다 — 새 라우트를 추가하고 vercel.json 을 안 고치면 CI 가 잡는다.
- 함정: `routes` 의 `status: 404` 는 `rewrites`/`headers` 와 **함께 쓸 수 없다**(Vercel 제약).
  정적 404.html 은 rewrite 로 보내면 200 이 된다. 상태코드를 우리가 정할 수 있는 곳은
  함수뿐이다.

## 8. 옛 정책 문구가 남아 손님을 돌려보낸 실수

- 잘못된 생각: 마감 정책은 전세차량 1시간·투어 8시간으로 통일됐다.
- 실제 결과: 화면 여러 곳이 여전히 **"12h cutoff" · "출발 12시간 전"** 이라고 안내했다
  (`CharterWizard` 헤더 칩, `CharterIntroModal`, `TourDetailPage`, 4개 언어 번역).
  실제로는 1시간 전까지 예약 가능한 손님에게 "이미 마감" 이라고 말하는 **과소약속**이었다.
- 재발 방지: 정책 숫자는 번역 문구에 손으로 적지 않는다. `{h}` 자리표시자를 두고 컴포넌트가
  상수에서 채운다. 그리고 `src/` 전체를 훑어 "12시간 마감" 문구가 다시 생기면 실패하는
  잠금 테스트를 둔다(주석의 설명은 허용).

## 이번 라운드의 한 줄

**"고쳤다"의 근거가 코드에 있는지, 문서에 있는지, 통과한 테스트가 실제 부작용을 재현하는지 —
셋은 전혀 다른 이야기다.** 여덟 건 중 여섯 건이 "기록은 있는데 실제로는 아니었다" 였고,
한 건(4번)은 **배포하고 네트워크를 뜯어봐야만** 보였다.
