# 본인 알림 키 교정과 재연결 주의

- 2026-09-21: 무작위 ECDH의 `getPrivateKey()`는 앞 0을 생략해 31바이트를 반환할 수 있다. 이를 32바이트 VAPID 테스트 자료로 쓰면 정상 키 검사도 간헐적으로 실패한다. `owner-vapid-diagnostics.test.ts`는 32바이트 합성 스칼라 1/2로 실제 공개키를 만들며, 서로 다른 키 쌍 거절도 유지한다. 운영 키·보안 검증기는 변경하지 않았다.
- Save 보고만으로 새 키 쌍 완료를 단정하지 않는다. 각 항목의 저장 성공과 마지막 서버 키 쌍 판정을 구분한다. 비밀키를 채팅/로그로 요청하지 않는다.
- 새 공개키가 배포돼도 기존 PushSubscription은 자동 교체되지 않는다. 실제 등록 클릭에서 기존 키를 비교하고, 실패한 unsubscribe 뒤에 새 구독을 겹쳐 만들지 않는다.
- 구독 변경은 scope/deviceHash도 바꾼다. 기존 제어 장부를 삭제하면 시작 시각/진행/중복 방지가 사라진다. 명시된 이전 기기에서만 원자적으로 이관한다.
- 발송 실패로 종료된 기록도 처리 이력이다. 새 기기에서 pending/attempts0으로 되살리지 않는다. 동일한 종료 상태·시도 횟수·원래 만료 시각으로 복제하고 원본을 보존한다.
- UI 합성 테스트는 실제 훅을 연결하되 인증/SW/Firestore를 메모리 경계로 대체한다. 시험 통과를 실제 Android 수신으로 보고하지 않는다.
- 로컬 합성 화면의 Vite 의존성 탐색은 해당 HTML로 한정한다. 앱 전체 진입점을 가짜 Firebase 경계로 해석하면 무관한 export 오류만 늘어난다.
- 임의 전체 검사를 추가하지 않는다. 변경된 경로 회귀/린트/실물 확인 후 저장소 기본 pre-push 게이트를 거쳐 한 번 묶어 배포한다.
