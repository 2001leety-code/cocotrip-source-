# 판촉·매출 P0 오답노트 — 2026-07-30

대상: 🌐웹(cocotripkr.com, Vercel=prod), PR #1191.

## 1. 방문자 수를 확인하지 않고 "트래픽 문제가 아니다" 라고 단정한 실수

- 잘못된 생각: 제휴 링크가 죽어 있고 측정이 없으니 매출 0의 원인은 구조다. 트래픽은 아니다.
- 실제 결과: 최근 30일 외부 방문자가 **41명**, 7일 **9명**이었다. 41명에서는 전환율을 논할
  표본 자체가 없다. 월 3,000 방문을 전제로 만든 매출 시나리오는 현황이 아니라 가설이었고,
  그 위에 "노출률 15%→70%면 $913" 같은 숫자를 예상 효과처럼 적었다.
- 재발 방지: 매출 분석을 시작하기 전에 **방문자 수를 먼저 실측**한다. 없으면 `NOT_CHECKED`
  로 두고, 전환율·매출 계산을 하지 않는다. 원인을 하나로 좁히지 않는다 — 트래픽과 동선은
  경쟁 관계가 아니라 둘 다 원인일 수 있다.
- 숫자를 쓸 때는 **실측 / 목표 / 가설**을 표에서 행으로 갈라 적는다. 같은 표에 섞으면
  읽는 사람이 전부 예측으로 읽는다.

## 2. 출발지를 언어로 추정한 실수

- 잘못된 생각: 사용자 언어를 알면 출발 도시를 추정할 수 있다. 한국어 → 서울.
- 실제 결과: 운영 홈의 항공권 링크가 `dcity=Seoul&acity=Seoul` — 서울에서 서울로 가는
  검색이었다. 호출부가 언어를 넘기지 않아 기본값 `ko` 가 쓰였고, 목적지 ICN 도 'Seoul' 이라
  둘이 같아졌다. 결과가 나올 수 없는 링크를 홈 첫 화면에 두고 있었다.
- 재발 방지: **모르는 값은 만들어내지 않는다.** 언어는 국적도 현재 위치도 아니다
  (한국어를 쓰는 재외국민, 영어를 쓰는 한국 거주자). 출발지를 모르면 목적지만 넣는다.
  출발지를 알더라도 도착지와 같으면 뺀다. 테스트가 이 조합을 차단한다.

## 3. 만든 측정이 배선됐다고 믿은 실수

- 잘못된 생각: `trackEsimClick` 이 정의돼 있으니 eSIM 클릭은 측정되고 있다.
- 실제 결과: 호출처가 **0건**이었다. 제휴 광고 5종(eSIM·호텔·항공·기차·렌터카) 전부
  `<a href>` 만 있고 클릭 핸들러가 없었다. "노출은 있는데 클릭이 0" 이 진짜인지 측정 누락인지
  구분할 수 없는 상태로 오래 있었다.
- 재발 방지: 측정 함수를 만들면 **호출처 수를 세는 테스트**를 같이 남긴다.
  죽은 측정 함수는 정의를 지운다 — 남겨두면 다음 사람이 "측정된다" 고 믿는다.
  제휴 링크를 노출하는 파일 목록을 테스트에 박아두고, 그중 클릭 측정이 없는 파일이 있으면 실패시킨다.

## 4. 노출을 컨테이너 단위로 기록한 실수

- 잘못된 생각: 슬라이드가 화면에 들어오면 그 안의 광고를 다 본 것이다.
- 실제 결과: `PreTripSlide` 가 컨테이너 진입 시 하단 제휴 6종을 전부 "봤다" 로 찍었다.
  윗부분만 보고 넘긴 사용자도 6종 노출로 집계돼, 노출 대비 클릭률이 실제보다 훨씬 낮게 보였다.
  광고가 효과 없다는 잘못된 결론으로 이어질 수 있었다.
- 재발 방지: 노출은 **카드마다** `IntersectionObserver`(threshold 0.5)로 기록한다.
  `IntersectionObserver` 가 없는 환경에서는 **기록하지 않는다** — "일단 기록" 하면
  보이지 않은 카드가 봤다고 남는다. 측정이 0인 것보다 거짓 노출이 더 나쁘다.

## 5. 쿠키 배너가 추적을 막는다고 믿은 실수

- 잘못된 생각: 쿠키 동의 배너가 있으니 동의 전에는 분석 도구가 안 돌 것이다.
- 실제 결과: `main.tsx` 가 부팅 즉시 `initGA()`·`bootPostHog()` 를 무조건 실행했다.
  배너는 localStorage 에 값만 쓰고 아무것도 막지 않았다. 사용자가 **닫기**를 눌러도 추적이
  계속됐다. 배너에 "동의하면" 이라 써 놓고 선택 전부터 이미 추적하고 있었던 것이다.
- 재발 방지: 동의 상태를 읽는 곳(`lib/consent.ts`)을 하나 두고, 배너는 그 함수로만 저장한다.
  `accepted` 일 때만 켠다. 미선택·닫기는 켜지 않는다(닫기 = 거부로 본다).
  UI 가 존재한다는 것과 그 UI 가 실제로 동작을 막는다는 것은 다르다 — 배선을 확인한다.

## 6. 제휴 파라미터를 두 파일에서 조립한 실수

- 잘못된 생각: 두 파일이 같은 환경변수를 읽으니 값은 항상 같다.
- 실제 결과: `src/data/hotels.ts` 가 `src/config/affiliateLinks.ts` 와 별개로 자기
  `TRIP_AFF` 를 조립하고 있었다. 계정을 바꾸거나 파라미터를 추가하면 한쪽만 바뀌어
  링크마다 다른 계정에 귀속된다. 수수료가 어디로 갔는지 추적 불가능해진다.
- 재발 방지: 조립은 한 곳(`tripAffiliateQuery()`)에서만 한다.
  다른 파일에 `Allianceid=${...}` 패턴이 나타나면 테스트가 실패한다.

## 7. 확인되지 않은 계정으로 노출을 늘릴 뻔한 실수

- 잘못된 생각: 모바일 홈에 제휴 카드가 없으니 넣으면 매출이 는다.
- 실제 결과: Vercel 에 `VITE_TRIPCOM_AFFILIATE_ID`·`VITE_TRIPCOM_SID` 가 **없었다.**
  코드에 옛 하드코딩 폴백이 남아 있어, 그대로 켰으면 **수수료 행선지를 모르는 계정으로**
  새 트래픽을 보내게 된다. 노출을 늘리는 것이 매출이 아니라 부채가 된다.
- 재발 방지: 새 제휴 노출은 **fail-closed** 로 만든다. 기능 플래그(`VITE_FEATURE_HOME_AFFILIATE`)
  **그리고** 설정 판정(`isAffiliateConfigured()` — 두 값이 모두 있고 숫자 형식)이 둘 다
  통과해야 렌더한다. 호출부와 컴포넌트 양쪽에서 막는다. 기존 노출의 폴백은 회귀 방지로 유지하되,
  **새 자리로 확대하지 않는다.**

## 8. 화면에 가격이 있다고 가정한 실수

- 잘못된 생각: AI 플래너는 $9.90 상품이니 어딘가에 가격이 적혀 있다.
- 실제 결과: `/planner` 입력 화면 DOM 에 가격 문자열이 **0건**이었고, 상단 배너만
  "free 1–3 day AI plan" 을 크게 말했다. 손님은 전부 공짜인 줄 알고 설문을 다 채운 뒤
  결제 단계에서 처음 $9.90 을 만난다. 그 지점이 이탈 지점이 된다.
- 재발 방지: 무료로 주는 것과 파는 것을 **입력 화면에서 먼저** 나눠 적는다
  (무료 미리보기 / 신규회원 쿠폰 / 전체 일정 유료). 프로모션 문구가 앞세우는 것과
  CTA 목적지를 일치시킨다 — 무료 일정을 말하면서 투어 목록으로 보내지 않는다.
  프론트와 서버 DEFAULT 를 **같이** 고친다(과거 한쪽만 고쳐 prod 가 옛 값을 반환한 사고가 있었다).

## 9. 자리표시자가 치환된다고 믿은 실수

- 잘못된 생각: 번역 문자열의 `{price}` 는 렌더 전에 다 채워진다.
- 실제 결과: `mypage.productLabels.ai_planner_full = "AI 플래너 ({price})"` 를
  `prettyProductLabel()` 이 `fillPrice` 없이 그대로 반환해, 예약 목록에 문자 그대로
  `AI 플래너 ({price})` 가 떴다. 손님이 자기 결제 내역에서 보는 화면이다.
- 재발 방지: 자리표시자가 있는 번역값을 반환하는 모든 경로에 치환을 붙이고,
  치환 함수를 거치는지 테스트로 잠근다.

## 10. 서버가 저장한 영어를 화면 언어로 착각한 실수

- 잘못된 생각: 화면이 4개 언어를 지원하니 마이페이지도 한국어로 나온다.
- 실제 결과: `pointHistory.description` 은 서버가 영어로 저장한 값이라, 한국어 화면에도
  `Ledger correction: removed AI-plan estimates …` 가 그대로 떴다. "내 코인이 왜 줄었지" 를
  설명해야 하는 자리가 아무것도 설명하지 못했다.
- 재발 방지: 저장값은 감사 기록이므로 바꾸지 않고, **화면에서만** 아는 형태를 번역한다
  (`lib/pointLogText.ts`). 모르는 문장은 원문 그대로 둔다 — 운영자가 손으로 쓴 설명까지 뭉개지 않는다.
- 같은 맥락: 누적 예약 수(원장)와 목록 개수(현재 이메일 조회)가 다르면 손님은
  "예약이 사라졌다" 로 읽는다. 각 숫자가 무엇을 세는지 라벨을 붙인다.

## 11. 검사 도구가 자기 자신에게 걸린 실수

- 잘못된 생각: 깨진 글자 검사기를 만들면서 예시로 깨진 글자를 주석에 넣어도 된다.
- 실제 결과: 레포 pre-commit mojibake 가드가 **검사기 소스 자체**를 깨진 문서로 보고
  커밋을 막았다. 같은 이유로 `hotels.ts` 의 기존 nullish 병합 연산자도 걸렸다.
- 재발 방지: 검사기가 찾는 패턴을 소스에 **글자 그대로 쓰지 않는다.** 전부 `\uXXXX`
  이스케이프로 적는다. 가드에 걸렸을 때 `--no-verify` 로 넘기지 않는다 — 가드가 옳고
  코드가 틀린 경우가 대부분이다.

## 12. 훅이 ref 를 돌려주게 만든 실수

- 잘못된 생각: 측정 훅이 `{ ref, onClick }` 을 돌려주면 호출부가 편하다.
- 실제 결과: 호출부가 렌더 도중 `aff.ref` 를 읽게 되고, 이는 React 에서 금지된 접근이다
  (`react-hooks/refs` 오류 10건). 렌더가 언제 몇 번 실행될지 모르기 때문이다.
- 재발 방지: ref 는 컴포넌트 밖으로 내보내지 않는다. 관찰이 필요하면 **껍데기 컴포넌트**
  (`<AffiliateCard>`)를 만들어 그 안에서만 ref 를 쓴다. 클릭 핸들러는 렌더 중이 아니라
  사용자가 누를 때 실행되므로 함수로 직접 내보내도 된다.

## 13. ESLint "오류 0" 을 주장하기 전에 기준선을 안 잡은 실수

- 잘못된 생각: 수정한 파일에 오류가 남아 있으면 내가 만든 것이다.
- 실제 결과: 9건 중 9건이 `origin/main` 에도 있는 기존 부채였다(같은 파일의 origin 버전을
  꺼내 lint 해서 확인). 내가 만든 오류는 ref 관련 10건이었고 그건 전부 고쳤다.
- 재발 방지: "오류 0" 을 말하기 전에 **origin/main 버전을 따로 lint 해 기준선**을 만든다.
  기존 부채를 내 것으로 세지도, 내 오류를 기존 부채로 숨기지도 않는다.

## 14. 부팅 경로만 막고 동의 게이트가 완성됐다고 믿은 실수

- 잘못된 생각: `main.tsx` 에서 `bootPostHog()` 를 조건부로 만들었으니 동의 전에는 PostHog 가 안 돈다.
- 실제 결과: **머지·배포 후 운영에서 직접 확인하니 여전히 `posthog.com` 요청이 나갔다.**
  `us-assets.i.posthog.com/array/...`, `us.i.posthog.com/i/v0/e/` 가 동의 `null` 상태에서 발생했다.
  원인은 `ensureInit()` 가 lazy-init 이라, `track()` 이 한 번이라도 불리면(App 의 `trackPageView` 등)
  그 경로로 SDK 가 켜졌기 때문이다. 부팅 문만 잠그고 옆문을 열어 둔 셈이다.
  (GA4 는 전송 함수가 `!window.gtag` 로 즉시 반환해 같은 문제가 없었다 — 우연히 안전했던 것이다.)
- 재발 방지: 게이트는 **자원이 켜지는 마지막 지점**에 둔다. PostHog 는 SDK 가 켜지는 문이
  `ensureInit()` 하나뿐이므로 거기서 막는다. 진입점이 여러 개인 기능은 진입점마다 막지 말고
  공통 병목을 찾는다.
- 더 중요한 교훈: **배포 후 실제 네트워크 요청을 보지 않았다면 이 구멍을 못 찾았다.**
  단위 테스트·빌드·CI 는 전부 통과했었다. 동의·추적처럼 "안 하는 것" 이 목적인 기능은
  코드 검사만으로 확인되지 않는다 — 운영에서 요청이 **안 나가는 것**을 눈으로 봐야 한다.

## 15. Service Worker 캐시를 잊고 배포 확인을 한 실수

- 잘못된 생각: 배포가 끝났고 페이지를 새로고침했으니 새 코드를 보고 있다.
- 실제 결과: SW 가 옛 번들(`entry-GRtpzM2z.js`)을 서빙해 **고치기 전 코드**를 검증하고 있었다.
  그 상태로 "항공 링크가 안 고쳐졌다 / GA4 가 동의 전에 돈다" 는 잘못된 결론을 낼 뻔했다.
- 재발 방지: 배포 확인 전에 **실제 로드된 번들 파일명을 먼저 확인**한다
  (`performance.getEntriesByType('resource')` 에서 `entry-*.js`). 배포 전 해시를 기록해 두고
  비교한다. 다르지 않으면 SW 등록 해제 + `caches.delete()` 후 다시 본다.
