# AI 센터 문의·정기검사 확장

## 이번 구현

- 기존 외부 받은함과 같은 AI 센터에 웹채팅 목록·대화·직접 답장을 추가했다. 완전히 합쳐진 시간순 받은함은 아니며 채널별 영역이다.
- 관리자 인증 후에만 DB를 초기화한다. 목록은 최근 50개 세션, 상세는 최근 50개 메시지로 제한하고 누락 가능성을 표시한다. 목록에 고객 본문·연락처·UID를 넣지 않는다.
- 수동 답장은 원문 그대로, 확인 버튼을 거쳐 저장한다. AI 생성·자동 번역·Telegram 발송은 이 경로에서 하지 않는다. 기존 고객 폴링과 같은 messages/from=admin/ts 형식을 쓴다.
- UUID·운영자·본문·원본 시각에 묶인 트랜잭션 영수증으로 같은 요청 재시도를 처리한다. 새 문의가 오면 409와 초안 보존, 불명확한 저장 결과는 같은 요청으로만 확인한다. 브라우저 종료 경고는 있지만 재시작 후 초안/UUID를 영구 보존하지 않는다.
- GitHub 공개 저장소의 실제 schedule/main 실행 100건에서 6종 검사 결과를 읽는다. 한 번 조회·5분 메모리 캐시이며 서버 인스턴스 사이의 영구 공유 캐시는 아니다. 조회 실패/이전 자료/최근 성공 없음/실행 지연을 구분한다. 휴대폰 알림은 이 표시만으로 활성화되지 않는다.
- 외부 메일·WhatsApp 답장을 위한 순수 정책·승인/발송 장부를 추가했다. 기본 OFF, 실제 API 연결 없음. 서버가 구성한 수신인·동의·현재 원본을 재검사하고 사람의 5분 승인, 중복 요청/불명확 결과 보호를 적용한다.

## 검증 범위와 한계

- 합성 웹채팅/정기검사 화면: ko/en/ja/zh × 390/1280px, 8건 통과. 검토/취소, 미리보기 실전송 차단, 44px 조작 영역, 가로 넘침 없음. 한국어 모바일/PC 캡처를 직접 확인했다.
- 새 집중검사: 웹채팅 서버 16, 문구/계약/화면 28, 정기검사 서버 16 및 화면/계약 18, 외부 응대 정책 74 및 장부 41. 전체 빌드·회귀는 정상 pre-push 결과로 별도 확인한다.
- 실제 공개 GitHub 읽기: 2026-09-09 00:05 KST경 최신 건강검사 34080730385/일정검사 34014698945 실패, 디자인·번역·보안·배포비용 검사는 성공이었다. 현재 이력이지 항상 정상이라는 보장이 아니다.
- 실고객 DB/실메시지/실폰 테스트는 하지 않았다. 전송기 callback은 전부 가짜다. 실제 예약·금액·AI 모델 호출·키·환경값·계정 권한은 변경하지 않았다.

## 운영 연결 전에 필요한 것

- Gmail 기존 수신 자격증명은 읽기 전용이다. 수신기 권한 검사를 약화하지 않고 별도 발송 권한/회사 계정 확인과 Reply-To·Message-ID·References·threadId 원본 연결이 필요하다.
- WhatsApp Business 앱 설치는 Cloud API 연결 증명이 아니다. 실제 회사 계정/번호 권한, 2시간 업무동의 세션과 24시간 고객응대 창, STOP/수동 앱 답장 반영, 동의한 시험 상대를 확인해야 한다.
- 외부 답장 장부 v1은 같은 수신 메시지당 최종 답장 1건이다. 확실히 발송 전 실패한 경우만 추가 1회 허용한다. 이미 승인/시도한 본문을 새 UUID로 덮어쓰지 않는다. 별도 추가 답장 업무는 새 설계/승인 경로가 필요하다.
- 보관 만료 필드가 있어도 실제 Firestore TTL 자동 삭제 설정은 아니다. 연결 전에 수신 데이터·초안·답장 영수증의 보관/삭제 정책을 확정해야 한다.
- Instagram/TikTok 메시지 API, 업체별 실제 청구액, AI 자동 답장, 휴대폰 실수신은 이번 구현에 포함되지 않는다. 전체 컨트롤타워 완성으로 보고하지 않는다.

## 모델 분담

Spark는 웹채팅 4언어 문구 및 정기검사 프론트 계약/문구 코드를 작성했다. 주 담당이 의미·시간 판정·표시 문구를 수정하고 통합했다. 직접 파일 쓰기 시도는 읽기 전용 제한으로 실패했으며 한도 소진으로 확인된 것이 아니다. 이후 도구 없는 코드 작성으로 범위를 줄였다. 서버 구현과 별도 회귀는 다른 사용 가능한 모델이 맡았고 주 담당이 최종 검토했다.
