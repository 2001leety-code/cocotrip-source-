# 개인용 운영센터: 실제 기록·알림 진단 개선

대상: 웹 cocotripkr.com / 개인 Android 컨트롤러. 사용자의 "계속하라니까 완료까지" 요청에 따라 기존 승인된 안전한 개발·검사·정상 머지·배포를 이어간다. 이 기록의 로컬 검사와 실제 운영 연결은 구분한다.

후속: 이후 사용자가 회사 문의 수신과 최소 저장을 승인했다. 이 문서의 당시 “별도 승인 질문” 상태는 [회사 받은함 후속 실행안](COMPANY-INBOX-CONNECTION-2026-09-08.md)으로 갱신한다. 본문의 이전 PR 구현/검증 기록 자체를 실제 계정 연결 성공으로 바꾸지는 않는다.

## 이번 변경

- AI 센터에 기존 `api_usage`의 Gemini 추정 사용액을 오늘/이번 달 두 칸으로 표시한다. 실제 업체 청구액·잔액·전체 API 비용이 아니다. 비용 단가나 저장된 금액을 수정하지 않는다.
- 한국 시간 기준 이번 달의 최신 기록 최대 501개를 읽고 최대 500개만 합산한다. 501번째는 한도 도달 판정에만 사용한다. 저장된 `service`, `ms`, `cost_usd`만 선택하며 계정·고객·요청 본문을 응답하지 않는다. 읽기 응답 대기는 3초로 제한한다.
- 유효한 기록 없음/조회 실패는 0원으로 만들지 않는다. 한도 도달·잘못된 금액·합계 정밀도 초과는 부분 자료로 표시한다. 금액은 USD 소수점 9자리 정밀도로 집계하며, 0으로 반올림될 만큼 작은 양수는 제외하고 부분 집계로 알린다. 원본 기록 자체는 변경하지 않는다.
- 기존 관리자 인증 뒤 동일 운영센터 요청에서 집계한다. 새 주기 호출·쓰기·자동 결제·알림 발송·외부 AI 호출은 없다. 비용 조회가 실패해도 정상 예약·문의 자료는 그대로 표시한다. 상단은 "일부 갱신"으로 알려 비용 장애를 숨기지 않는다.
- 서버 알림은 기존 설정 판정 결과만 `off`/`configuration_required`/`configured`/`unknown` 네 값으로 표시한다. 기기 식별자·키·설정 원문은 반환하지 않는다. `configured`도 실제 수신 확인이 아니며 `deliveryVerified`는 항상 false다. 기기 등록, 설정 충족, 실제 휴대폰 수신을 구분한다.
- 핵심 금액과 상태는 바로 보이고 긴 기준 설명은 접는다. 네 언어, 키보드 초점, 44px 누름 영역, 작은 화면 넘침을 검사한다.
- Android 검사에 실제 APK의 버전명·버전코드 일치를 추가했다. 소스 설정만 최신이고 설치 파일은 구버전인 경우를 통과시키지 않는다. 앱 코드·서명·권한은 바꾸지 않았다.
- 불국사·남이섬 두 사진만 AVIF 색상 압축을 조정했다. 원본·구도·치수·WebP·다른 18개 사진·이전 캐시 주소는 유지한다. 새 36개 파일 합계는 1,610,998 → 1,443,856바이트로 줄었다. 실제 전송 총량이나 운영 속도 개선으로 확대하지 않는다.

## 실제 로컬 검증

- 최종 `npm run build`, 네 언어 2,214키 검사, 변경 소스 ESLint, 용량 8그룹 PASS. 초기 전체 단위검사에서 6개가 실패했다. 새 알림 상태 영역 때문에 이름 없는 `getByRole('status')`가 두 곳을 찾는 검사 오류였으며, 실제 갱신 상태에 접근성 이름을 부여하고 검사를 그 영역으로 한정했다. 관련 116개 재검사는 PASS다. 최종 전체 단위검사는 정상 pre-push에서 다시 실행한다.
- 실제 AI 센터 개발 하네스에서 390/1280px × 네 언어 × 8개 상태 = 64개 PASS. 금액/기록 없음/부분/실패/이전 자료/갱신 상태/접기·펼치기/키보드 초점/44px/넘침0/페이지 오류0 확인. 근거 `tmp/owner-integrated-panels-r3-20260908/report.json`.
- 독립 비용 패널 검사는 같은 두 화면 크기 × 네 언어 × 7개 상태 = 56개 PASS. 실제 통합 화면 검사와 별도다. 근거 `tmp/admin-recorded-usage-visual-20260908/summary.json`.
- 로컬은 가짜 공개 Firebase 설정을 해당 검사 프로세스에만 넣었다. 실제 환경 파일·고객 자료를 읽지 않았으며 실제 API와 외부 호출·쓰기는 브라우저에서 차단했다. 첫 로컬 환경 누락에 따른 `auth/invalid-api-key`와 검사 캡처 시 고정 헤더에 가린 제목을 제품 결함이나 성공 증거로 세지 않았다.
- 실제 최신 APK는 버전 1.0.1/코드 2, SHA-256 `577355c48b9a7f0d5e6a6feb277b2c79a609707433dc054ea7441388aa64d751`. 새 버전 검사 통과. 별도 main 폴더에 남아 있는 1.0.0/코드 1 파일은 실패했다. 파일 서명 검증과 실기기 로그인·수신 성공은 다르다.
- 사진 36개는 동일 조리법으로 재생성해 바이트까지 일치하고 각각 작아졌다. 원본 20개 해시·WebP 151개 보존을 별도 검토자가 확인했다. 실제 390/1280px의 이전/이후 사진 요청·치수·구도·대체 텍스트·필터·상세 이동·뒤로가기 62조건 PASS. 모의 데이터/외부 차단에 따른 콘솔 메시지는 실제 제품 오류와 구분했다.
- 같은 빌드에서 사진 응답 바이트만 이전/이후로 대조한 Lighthouse 12.6.1 측정도 수행했다. 두 비교에 동일한 화면 이동을 적용해 지연 로드 사진의 실제 요청을 보장했고 desktop 1350×940, CPU 1배, 네트워크 조건과 응답 헤더를 맞췄다. 이전은 사진 두 개·예상 낭비 9,654바이트·image-delivery 0.5를 재현했다. 이후 실제 12,560/12,198바이트 AVIF 두 개를 받은 뒤 같은 검사가 최적화 대상 0개(`notApplicable`)였다. 이는 원래 무조작 페이지 수집과 다른 동일 스크롤 비교이며, 단회 종합 점수 98→99를 운영 속도 향상으로 단정하지 않는다. 기존 미사용 CSS/JS·요청 의존성 판정은 남아 있고 기준을 완화하지 않았다. 원본: `tmp/lighthouse-tour-compression-20260908/before-scroll-r2` 및 `after-scroll`.
- 최종 배포 산출물 175개 JS/CSS에서 새 개발 하네스 표식 0개, 초기 커뮤니티 선택자 0개, Lighthouse 필수 판정 설정 변경 0개를 확인했다. root가 별도로 PC·모바일의 접힌/펼친 비용 패널 4장을 직접 확인했다.

## 실제 연결에서 필요한 것

- 기존 Brain의 회사 Gmail 읽기·답장·문의 전환 코드는 존재하지만 현재 통합센터와 연결되어 있지 않다. 문의 전환에는 메시지 식별자 중복 방지가 없고, 직접 답장과 웹 승인/발송 장부 계약도 다르다. 기존 코드를 그대로 자동 응대로 켜지 않는다.
- WhatsApp은 연락 링크만 확인됐으며 실제 수신용 서버 연결은 없다. 회사 메시지 접근·최소 저장에 대한 별도 승인 질문은 전달했다. 개인 메일, 고객 본문의 외부 AI 전송, 실제 자동답변 활성화는 그 질문의 범위에서도 제외했다.
- 실제 서버 알림 활성화에 필요한 값은 운영자가 **Vercel → Production 환경변수**에 직접 설정해야 한다. AI가 비밀값을 읽거나 설정을 바꾸지 않는다. 이 PR에 새 환경변수·인증·개인정보 보관 정책 변경은 없다.
- 검사 당시 ADB 연결 기기는 0대다. 실제 휴대폰의 로그인·기기 등록·잠금 중 수신·PC OFF 수신과 업데이트 전환을 모의 브라우저/파일 검증으로 대체하지 않는다.
- Hermes 이전, 전체 청구 API 연동, 실제 고객 자동응대가 완료됐다고 보고하지 않는다. PC의 로컬 Gmail 감시기를 끈 뒤에도 실행하려면 별도의 상시 실행 환경과 승인된 계정 연결이 필요하다.

## 반영 상태

최종 전체 회귀 → 단일 묶음 푸시 → 정상 PR 검사/머지 → 운영 배포 실확인 순서로 진행한다. 정확한 PR·배포·최종 전체 검사 수치는 해당 PR 본문과 Brain 공유 작업 기록에 남긴다. 이 문서의 로컬 PASS를 운영 인증 화면이나 실제 고객 메시지·휴대폰 알림의 성공으로 읽지 않는다.
