# 개인용 컨트롤러 완성 전 남은 연결과 검증

작성: 2026-09-07. 제품 기준 main ac0e676dd3499bfe954939448c9ec04ca9f2a9a7.
이 문서는 현재 코드와 설정 이름을 대조한 실행안이며, 아래 제안 기능이 이미 배포됐다는 뜻이 아니다.

## 완료 기준

1. 기존 Android 앱에서 운영센터를 열고 본인 계정으로 필요한 업무를 확인할 수 있다.
2. 새 예약과 문의가 정해진 시간 안에 본인 휴대폰 알림으로 도착한다. 전송 서비스 접수와 실제 화면 수신을 구분한다.
3. 알림 클릭과 다른 창의 업데이트가 작성/결제 중인 화면을 갑자기 바꾸지 않는다.
4. 메일·WhatsApp·비용 항목은 실제 연결 범위와 최신 확인 시각을 표시한다. 미연동/추정/조회 실패를 정상이나 0원으로 바꾸지 않는다.
5. PC가 꺼진 상태에서도 서버 측 연결이 동작하고, 휴대폰의 실제 수신·진입·새 버전 전환을 확인한다.

## 이번에 승인 없이 먼저 할 수 있는 안전한 보완

- 외부 호출 없는 Lighthouse 결과 판독기와 가짜 보고서 검사를 만든다. 실제 세 페이지의 누락/중복, 로그인 이동, 실행 오류, 필수 평가 실패를 거부한다. 기존 점수 기준은 낮추지 않는다.
- 운영센터 email_retry 표시와 같은 원본의 긴급 업무 제목을 4개 언어의 '고객 메일 발신 재시도'로 명확히 한다. 긴급 업무는 실제 생성 코드의 식별값 4개와 예상 제목 형식이 맞을 때만 적용한다. API, 상태, 상세 문구, 수량, 데이터, 링크, 발송 방식은 그대로 둔다.
- 관련 검사, 린트, 빌드, 실제 브라우저 확인과 오답노트를 갱신한다. 준비한 판독기가 워크플로에 연결되기 전에는 CI 문제가 해결됐다고 표시하지 않는다.

## 별도 승인 대기: 본인 휴대폰 운영 알림

직접 결제 성공 처리에 붙이기보다 별도 서버 확인 작업으로 시작하는 안이다. 예약/문의의 필요한 상태 필드만 조회하고, 원본 성공 여부를 바꾸지 않는다.

- 제안 주기: 5분. 즉시 실시간 알림으로 표현하지 않는다. Vercel에는 기존 5분 예약 작업들이 있으나 신규 일정은 아직 연결하지 않았다.
- 제안 신규 파일: api/_shared/owner-notification-policy.js, api/_shared/owner-notification-delivery.js, api/_crons/owner-notification-sweep.js. 일정 연결은 api/cron-runner.js와 vercel.json.
- 첫 시작 시점 이전 기록은 소급 발송하지 않는다. 현재 운영센터의 최근 N건 조회를 재사용하지 않고 이어 읽는 위치를 보존해 많은 사건도 빠뜨리지 않는다.
- 잠금화면 문구는 '새 예약이 접수되었습니다. 운영센터에서 확인하세요.' 같은 고정 안내다. 고객명·이메일·전화·금액·일정·예약번호를 title/body/url/tag에 넣지 않는다. 이동은 /admin/ai-center로 한정한다.
- 수신자는 요청 본문 UID나 이메일을 믿지 않고 서버에서 본인 관리자 자격과 선택된 휴대폰 등록을 확인한다. 기존 모든 등록 기기로 보내는 방식은 그대로 확장하지 않는다.
- 같은 사건의 중복, 동시에 실행된 작업, 전송 일부 성공, 시간 초과로 결과가 불명확한 상태를 구분한다. 기기별 결과를 기록하며 성공한 기기로 전부 재발송하지 않는다.
- 새 전송 장부에 보관할 최소 필드/보관 기간, 실제 수신 기기, 활성화 범위는 확정 전이다. 권한·외부 전송·개인정보 관련 사항을 AI가 임의로 활성화하지 않는다.
- 신규 발송 플래그는 기본 꺼짐으로 준비한다. 실제 활성화와 고정 문구의 본인 테스트 알림은 휴대폰 등록 확인 뒤 별도로 승인받는다.

## 별도 승인 대기: 유효한 Lighthouse 연결

- .github/workflows/pr-lighthouse.yml과 .lighthouserc.json, 새 scripts/lighthouse-preview-auth.cjs를 연결한다.
- 기존 GitHub Secrets의 VERCEL_AUTOMATION_BYPASS_SECRET을 해당 미리보기 origin에만 사용해 쿠키를 준비한다. 키를 URL query, 로그, 결과 보고서, 외부 폰트 요청에 넣지 않는다.
- continue-on-error를 제거하고 실제 세 페이지 결과를 별도로 판독한다. 보고서 누락/로그인 페이지/실행 오류/필수 평가 실패를 실패로 처리한다. 경고 등급과 점수 기준은 그대로 둔다.
- 판독기만으로 결과가 같은 실행에서 만들어졌는지는 증명할 수 없다. 실행별 빈 결과 폴더를 사용하고 수집 → 평가 → 판독 순서의 성공을 작업 흐름에서 보장해야 한다. 실제 LHCI는 실패한 평가만 저장하므로 빈 assertion 배열 자체는 정상일 수 있지만, 파일 누락은 실패다.
- 공개 임시 보고서 업로드는 끄고, 비밀 정보가 포함되지 않은 자료만 제한된 저장소에 보관하는 안을 사용한다.
- 기존 visual/smoke 인증 연결, Vercel 보호 설정, Firebase 권한, 키 값은 변경하지 않는다. 새 검사 결과가 기존 제품 문제를 드러내면 기준을 낮춰 녹색으로 만들지 않는다.

## 끝내기 전

승인과 기기 확인 전에는 전체 목표를 완료로 표시하지 않는다. 승인된 코드 변경을 한 브랜치에 모으고 전체 검사/브라우저 확인 뒤 한 번 푸시한다. PR 머지와 운영 READY/버전/공개 경로를 확인하고 main/origin/main 차이, 열린 PR, 작업 기록을 남긴다.
