운영자가 위 실행안을 보고 새로 답한 "진행해"를 근거로 입력/결제 업데이트 보호, 본인 기기 예약·미처리 신규문의 연결, 보호된 미리보기의 Lighthouse 검사 연결을 구현했다. 한 브랜치의 검증·푸시·머지·배포 확인까지 승인 범위다. 실제 알림 활성화와 본인 테스트 발송은 별도 확인 전까지 실행하지 않는다.

- PWA: 실제 새로고침 직전에 입력·결제·백그라운드·그 사이 새 조작·유효시간을 다시 확인한다. 설치 라이브러리 원본을 실행한 회귀검사로 다른 창의 업데이트가 기존 보호를 우회하던 경우도 재현·차단했다. 운영 알림 클릭은 기존 운영센터 창을 초점 이동만 하거나 새 창을 열며 다른 작성 화면을 이동시키지 않는다.
- 본인 알림: 기본 OFF의 5분 서버 확인 작업을 연결했다. 본인 관리자와 지정 구독 한 대를 매 전송 직전 재확인한다. 원본 자료는 최소 필드만 읽고 수정하지 않는다. 전송 장부에는 고정 상태·해시를, 이어 읽기 위치에는 암호화한 식별자를 사용한다. 활성화 전 기기·언어·보관기간 결정과 실기기 확인이 남는다. 상세 계약은 [활성화 전 확인서](OWNER-NOTIFICATION-RUNBOOK-2026-09-07.md)를 따른다.
- 알림의 제한: 모든 과거 기록이나 모든 새 문의 이력 알림이 아니다. 최초 활성화 뒤 새로 생긴 예약과 최초 조회 때 아직 열려 있는 새 문의가 대상이다. 메일 수신·WhatsApp·API 비용 알림은 이 연결에 포함하지 않았다. 5분은 확인 주기이지 수신 시간 보장이 아니다.
- 배포 검사: 신뢰한 main의 검사 도구만 사용하고 같은 저장소 PR의 정확한 Preview 배포를 확인한다. 기존 비밀값은 해당 호스트의 서버 요청에서만 인증 쿠키 준비에 사용한다. 브라우저 요청 헤더/URL/공개 보고서에 키를 넣지 않는다. 평가 실패를 숨기지 않고 실제 세 페이지 결과를 검사한다. 첫 머지 뒤 main에서 같은 Preview 배포 ID를 지정해 실제 성공 여부를 확인해야 하며, 그 전에는 실제 CI 해결 완료로 표시하지 않는다.
- 실제 로컬 브라우저: 자동 요청 뒤 입력 시작, 수동 요청 뒤 재입력, 가짜 결제 프레임 중 업데이트 보류에서 새로고침 0회와 메모 유지 확인. 보호 종료 후 수동 적용은 1회이며 추가 활성화 요청 없음. 다른 창에서 준비된 업데이트는 요청 없이 0회다. 390px/1280px, 네 언어, 44px 버튼, 키보드 초점/닫기, 두 인트로와 자산 4개 HTTP 200을 확인했다. 실제 결제·고객 자료·푸시 전송 없는 개발용 모의 화면이다.

1. 기존 Android 앱에서 운영센터를 열고 본인 계정으로 필요한 업무를 확인할 수 있다.

## 승인 전 실행안: 유효한 Lighthouse 연결 (이번 답변으로 승인)
