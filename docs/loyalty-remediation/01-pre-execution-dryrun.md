## 판별 기준

**돈으로 인정** — 서버가 검증한 PayPal Capture + orderID + captureID + 통화 USD + 금액 일치 +
`paymentVerified === true` + 테스트·관리자 우회·무료 쿠폰 아님 + 같은 orderID 1회만 + 환불 누계 반영.

**돈이 아님** — AI 예상 여행 경비, `ADMIN-BYPASS-`/`TEST-` 주문, 무료 쿠폰·무료 재생성,
결제 원장 없이 `AI Plan: … ($금액)` 형태로 생성된 적립.

**애매** — 근거가 불완전하면 차감하지 않고 개수만 보고한다.

## 🔴 여기서 드러난 사실 — 전체 재계산을 쓰지 않은 이유

운영 `bookings` 29건 중 **`uid` 필드가 있는 것 0건, `paymentVerified === true` 0건**.
두 필드는 같은 날 PR #1187 에서 추가됐고 그 이전 결제 문서에는 없다.

"필드가 없다" 를 "검증 실패" 로 취급하면 과거 실제 결제가 전부 $0 으로 밀린다.
그래서 판별을 셋으로 나눴다.

| 상태 | 판정 |
|---|---|
| `paymentVerified === false` | 돈 아님 (차감) |
| 필드 자체가 없음 | **애매 — 차감하지 않음** |
| 계정 귀속 검증 주문 0건인데 지출이 남음 | **재계산 금지** |

결과적으로 4계정 **전부 `subtract_pollution_only`**(명백한 오염분만 차감).
