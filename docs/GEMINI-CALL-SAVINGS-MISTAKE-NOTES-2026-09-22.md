# Gemini 중복 호출 절감 · 2026-09-22

- 긴 문의는 번역 캐시가 있어도 언어 판별을 반복했다. 성공한 판별만 기존 100개 메모리 캐시에 넣는다. 실패·잘못된 응답은 재시도하며 새 영구 고객 저장소는 만들지 않는다.
- 일정 생성의 기존 시간 제한 9곳은 대기만 종료했다. 공통 `withTimeout`이 SDK에 취소 신호를 전달하고 완료 시 타이머를 정리한다. 프롬프트·모델·재시도 횟수·식이 검증은 유지한다. 전송 중단이 제공자의 처리·과금 중단을 보장하지는 않는다.
- 콘텐츠 초안은 같은 날 재실행 때마다 다시 생성했다. 기존 `content_drafts/kst-{dayIndex}`에 공개 소재·초안을 재사용하고, 10분 생성 잠금과 소유 토큰으로 동시 생성·오래된 실행의 덮어쓰기를 막는다. 잠금 실패 시 기존 최선의 저장·발송 경로를 유지한다. DB 장애 중의 호출 중복이나 정확히 한 번 발송은 보장하지 않는다.
- 수정안 검수에서 잠금 조회 실패 후 기존 `.add()` 저장을 건너뛰던 새 회귀를 발견해 보완했다. 오류·동시 실행·만료 복구를 실제 작업 함수와 가짜 Firestore로 검사했다.
- 최종 외부 통신 차단 환경: 관련 36파일 436검사 통과, 변경 JS/TS 8파일 ESLint 오류·경고 0, `npm run build -- --outDir tmp/gemini-savings-20260922/build` 1회 통과. 기존 전체 852파일 검사는 재실행하지 않았다. 필요한 회귀 검사 16개(새 테스트 파일 2개)를 추가했다.
- 반복 방지: 작업 중에는 관련 검사, 배포 시에는 기존 pre-push 전체 검사와 GitHub 검사를 사용한다. 보호 훅·CI·기준·기존 테스트는 삭제하거나 완화하지 않는다.
- 위 결과는 최초 로컬 완료 시점의 기록이다. 당시 로컬 변경만 완료했다. 운영 키·DB·유료 API·실제 발송·환경변수 변경·새 배포는 실행하지 않았다. 검증 로그는 `tmp/gemini-savings-20260922/`에 있다.

- 배포 검사에서 기존 content-draft HTTP 진입점의 인증 누락(P44)을 발견했다. 사용자 승인 후 기존 `verifyCronRequest`를 작업 앞에 연결한다. cron/admin 정책·허용 목록은 유지하며 무인증·위조 헤더·잘못된 Bearer의 401과 부작용 차단을 실제 HTTP 핸들러 회귀 검사로 확인한다. 첫 pre-push는 build/전체 unit 854파일 11,768통과·TODO1/size-limit 통과 후 P44에서 중단됐으며 훅을 우회하지 않았다.
- 인증 보완 후 외부 통신 차단 환경에서 실제 HTTP/cron 인증 관련 2파일 27검사 통과, 변경 파일 ESLint 통과, mistake-lint 201 OK·위반 0. 배포 결과는 후속 배포 기록에서 확인한다.
