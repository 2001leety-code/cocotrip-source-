# 최근 일정 이력 연결 오답노트 (2026-09-28)

- 원인: 건강 검사는 Firebase 로그인 토큰을 보내지만 요청 본문에 `uid`를 넣지 않는다. 기존 셰이퍼는 본문 `uid`만 읽어 최근 일정 조회를 건너뛰었다. 비회원 이메일로 과거 기록을 찾는 방식은 신원 증명이 되지 않는다.
- 수정: 토큰에서 검증된 UID만 별도 `verifiedHistoryUid`로 새 일정에 저장하고, 이 필드로 최근 일정 3건만 조회한다. 토큰이 없는 비회원과 과거 출처 불명 기록은 연결하지 않는다.
- 밟은 함정: 검증 UID를 기존 플랜 소유 UID까지 전파하자, 본문에 UID가 없는 기존 결제 흐름의 접근 토큰이 사라져 통합 검사 3건이 403으로 실패했다. 이력 신원과 플랜 접근 권한을 분리해 복구했다.
- 회귀 확인: 전체 플래너 저장→다시 읽기, 동기·비동기 저장, 비회원·위조 UID, 최근 기록 조회·복합 색인, 공개 플랜의 새 UID 필드 마스킹을 검사한다.
- 남은 운영 확인: 새 필드는 과거 계획에 소급되지 않는다. 색인이 배포된 뒤 Daily Health의 다양성 중복률을 다시 측정해야 한다.
