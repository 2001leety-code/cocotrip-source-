# /planner 정보 밀도 오답노트 — 2026-08-31

## 놓친 것

- 주간 디자인 검사는 제목·주요 버튼·터치 크기·가로 넘침을 검사했지만, 한 화면에
  보이는 문장 수와 페이지 전체 길이는 검사하지 않았다. 검사가 초록이어도 사용자는
  긴 설명을 보고 복잡한 서비스로 느낄 수 있다.
- 색인용 본문을 모두 펼쳐 두면서 거래 화면과 설명 문서를 한 페이지에 겹쳤다.
- 모바일 모드 카드 안에서 이미 전달한 설명을 선택 카드 아래에 한 번 더 보여 첫 질문을
  화면 밖으로 밀었다.

## 다시 지킬 기준

1. 390px 안팎의 첫 화면에서 핵심 주장, 모드, 실제 가격, 첫 질문 순서를 유지한다.
2. 가격 값과 무료·유료 경계는 첫 질문 전에 남긴다. 금액 정본과 결제 배선은 디자인
   압축 작업에서 건드리지 않는다.
3. 먼저 보이는 장점은 세 개로 제한하고, 과정·지원 범위·FAQ·근거 전문은 키보드로 열 수
   있는 native `details`에 둔다.
4. 접힌 본문도 DOM과 FAQ 구조화 데이터에는 남긴다. 이 경우 색인 분량 회귀 테스트는
   화면에 그려진 `innerText`가 아니라 전체 DOM `textContent`를 검사한다.
5. `summary`는 최소 44px이며 포커스 표시가 보여야 한다. 4개 언어는 같은 구조로 제공한다.
6. 제목을 접을 때도 native `h2`를 `summary` 안에 남긴다. 일반 `span`으로 바꾸면
   화면낭독기 제목 탐색과 검색 문서 구조가 동시에 약해진다.

## 검증 함정

- 로컬 공개 화면도 Firebase 웹 설정이 완전히 비어 있으면 앱이 빈 화면으로 끝난다.
  운영 키를 복사하지 말고, 인증을 쓰지 않는 UI 검증에는 문법상 유효한 가짜 설정을
  dev 서버 프로세스에만 넣는다.
- 한 로컬 Vite 서버에 Playwright 작업자를 많이 붙였을 때 간헐적으로 빈 화면이 나오면
  기능 실패로 단정하지 않는다. 먼저 콘솔 오류를 수집하고 동일 스펙을 `--workers=1`로
  재현한다. 직렬에서도 실패할 때만 화면 회귀로 판정한다.
- KST 기준으로 내일 이후만 허용하는 테스트에 고정 여행 날짜를 쓰면 그 날짜의 자정에
  제품과 무관하게 깨진다. 여행 날짜를 검증하는 테스트는 시스템 시각도 함께 고정한다.
- 배지 금지 문구를 검사할 때 카드 전체에서 `best` 같은 일반 단어를 찾으면 계절 안내
  문장까지 오탐한다. 금지 표시는 실제 배지 영역 안에서만 검사한다.
