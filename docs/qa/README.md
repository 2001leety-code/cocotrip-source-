# CocoTrip 기능 점검 관리

정본은 [91개 기능 관리표](feature-checklist.csv)다. 고객 38·관리자 28·MOOD 16·연결 9개를 유지한다. 기능 수와 테스트 수는 정상 작동 비율이 아니다. 기존 바탕화면 관리표는 갱신하지 않는다.

## 판정 기준

- 코드 확인: 실제 라우트·요청·처리 경로를 찾은 상태. 실행 성공이 아니다.
- 로컬 부분 확인: 명시한 화면·함수·분기를 실행했다. 대체한 경계와 빠진 분기를 기록한다.
- 로컬 흐름 확인: 같은 합성 입력/문서를 요청→처리→저장→조회/표시까지 추적했다.
- 운영 확인: 배포 환경에서 대상 기능의 결과까지 확인했다. HTTP 200, 배포 READY, mock 통과만으로 이 상태를 주지 않는다.
- 실패/미확인: 재현된 실패와 아직 실행하지 않은 것을 구분한다. 완료 체크는 해당 기능의 남은 조건이 모두 해소됐을 때만 바꾼다.

공통 확인은 정상 입력, 필수 입력 누락, 조회·서버 오류, 재시도, 중복 실행, 입력/표시/저장 일치다. 해당하지 않는 조건에는 이유를 남긴다. 결제·권한·개인정보·식이 보호를 완화해 검사를 통과시키지 않는다.

## 검사는 세 번의 목적에 맞춰 실행

| 종류 | 실행 시점 | 실제 명령/범위 | 통과가 뜻하는 것 |
|---|---|---|---|
| 빠른 변경 검사 | 수정 중 | `npm run test:unit -- <관련 파일> --maxWorkers=1`, 변경 파일 ESLint | 수정한 계약과 회귀 사례 확인 |
| 고객 흐름 | 연결 동작 변경 후 | 기존 `tests/playwright-charter-local.config.ts`, `tests/run-inquiry-local.py`, 플래너 journey 검사 | 명시한 실제 UI/처리와 합성 경계의 연결 확인 |
| 출시 필수 | 변경을 모두 모은 뒤 한 번 | 정상 `git push`의 `scripts/git-hooks/pre-push`: build·전체 unit·size·오답패턴·hooks | 저장소의 출시 회귀 기준. CI/실제 배포 결과는 별도 확인 |

`check:types`는 `npm run build` 별칭이다. `verify:all`도 실제 빌드를 실행한다. `tsc --noEmit`을 타입 통과 근거로 사용하지 않는다. 같은 변경에 `verify:all`, `verify:prepush`, 정상 push를 연속 실행하면 전체 검사가 중복된다. 수정 중에는 관련 검사, 마지막에는 정상 훅을 사용한다. 필수 검사를 삭제하거나 skip하지 않는다.

메일/PDF 보안 의존성 변경 후 실행 환경은 Node 22계열이다. 로컬은 기존 Chromium의 요구 조건을 만족하는 22.17 이상을 사용한다(이번 검증 22.23.2). CI도 22로 맞췄고 Vercel은 원래 22.x였다. 운영 설정·키는 변경하지 않았다. 공유 node_modules에 직접 설치하지 않고 독립 설치와 잠금 파일의 Linux 패키지 보존을 확인한다. 보안 검사는 `npm audit --omit=dev --json` 결과를 기존 `scripts/audit-gate.mjs`로 판정하며, 제거한 extract-zip의 이전 예외도 삭제했다.

일반 Vite 설정에는 운영 API 프록시가 있다. 격리 검사는 `tests/charter-local-server.mjs`처럼 `configFile:false`, 빈 env 디렉터리, 합성 설정, 로컬 API 차단을 사용한다. 브라우저는 별도로 외부 요청/서비스워커를 차단한다. 메일·Sheets SDK는 fetch mock만으로 차단되지 않으므로 각 외부 SDK도 대체한다.

## Gemini 호출과 비용 확인

| 경로 | 코드상 호출 조건 | 이번 확인/남은 한계 |
|---|---|---|
| 무료 미리보기 | `api/ai-planner-quick.js`: 최대 2회, 첫 요청 30초·재시도 18초, thinking 0. 응답 후 검증 실패도 재시도 조건 | 실제 동시 제출 2회→1회 수정. 클라이언트는 transport TypeError만 1회 재시도하므로 서버 모델 시도는 최악 4회 가능 |
| 전체 생성 | `handlerCore.js`가 block-mode 가능 여부를 먼저 확인하고 실패/부족 시 `geminiPipeline.js`의 legacy 또는 설정된 3pass로 진행 | 실제 legacy·block 동기 및 block worker callback의 저장/조회 확인. SDK/작업 스케줄러는 대역이며 실서비스 재시도·streaming·3pass 증거로 확대하지 않음 |
| 추가 생성 | 식이·패턴 검증 재시도, 토큰 제한 재시도, 설정된 모델 승격·캐시 대체 | 조건부 품질/복구 경로. 실제 불필요함을 재현하지 않은 재시도는 삭제하지 않음 |
| 관측 | `api/_shared/apiUsageRecorder.js`의 `api_usage`와 기존 관리자 화면 | 기록 실패를 허용하는 방식이므로 청구 원장과 같지 않음. thinking 토큰은 현재 출력 토큰 집계에 별도로 포함하지 않음 |

동일 훅의 진행 중 가드는 다른 탭·기기·직접 API 요청을 막지 않는다. 응답 유실 후 transport 재시도로 모델이 다시 실행될 가능성은 남아 있다. 서버 중복 방지나 비용 산식 수정은 별도 재현·정책 검토 후 진행한다. 이번 정리에서 유료 모델 호출과 운영 사용량 조회는 하지 않았다.

## 남은 작업의 기준

관리표의 `다음 확인`을 작업 단위로 삼는다. 관련 실행 근거가 없으면 완료로 바꾸지 않는다. 같은 문서의 흐름 근거는 [플래너 실행 기록](../PLANNER-JOURNEY-CHECKLIST-2026-09-23.md), 순서는 [정리 계획](../superpowers/plans/2026-09-23-cocotrip-system-cleanup.md)을 따른다. 새 유료 서비스·플러그인을 추가할 근거는 현재 없다.
